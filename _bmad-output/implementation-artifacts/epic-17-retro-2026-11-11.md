## 2. What went well

- **The production logs again gave the reproduction.** 17-1 started from the exact input the log recorded, and 17-3 read a month of them (743 creations with an ISBN, all 13 digits) to bound what the old manual form could have stored before writing the repair.
- **DRY held on the entry paths.** The title page reuses the catalog's V-code arm, every form reuses one ISBN function, both title forms reuse one UPC check; each fix landed once.
- **Rule #20 kept the repair small.** The repair rewrites only what the one rule accepts and writes differently; everything else is left and logged.
- **The documentation review found a real defect.** Writing the manual for the edit form surfaced #676 before release, not after.
- **Defaults inactive, never updated** made 17-6 easy to reason about: nothing an admin wrote can be overwritten.

## 3. What did not go well

- **An add-vs-delete race became easier to reach (#663 item 2).** Creating a volume reads its title without a lock; deleting a title locks it and counts live volumes. In between, a delete can commit and leave a live volume on a trashed title, which the auto-purge then removes. Pre-existing, but 17-2 puts both actions on one screen. A share lock on the title row in the insert transaction would serialise them (Rule #22).
- **Rule #20 deviation in 17-3.** No production ISBN export existed, so the corpus check over real data was replaced by a reading of the production logs — which start on 2026-10-26, so titles up to about id 280 were never read — with one `info` line per rewrite so that every change stays auditable after the fact. This was the project lead's decision (2026-11-10). The corpus test remains, `#[ignore]`d, for a later run against an export.
- **A review decision of mine was reversed after the fact (#669 → PR #671).** I first let a trashed title colliding with a live one block the live repair. On reflection that let the Trash hold a live title hostage; the rule became "the Trash never blocks a live title". It cost one more PR on the critical path.
- **The CI runner moved under us.** GitHub's `ubuntu-latest` became 26.04, where Playwright 1.59 cannot install Chromium. The E2E jobs were pinned to `ubuntu-24.04` (#659); the upgrade is tracked in #660. Until then the pin is debt that will bite when 24.04 runners go away.
- **A #676-class defect was found only by the documentation review.** A 4xx refusal on the title edit form and the wish list was not swapped by HTMX: the page showed a generic error or nothing. No E2E covered a refusal on an edit form, so every story that added a refusal passed. Fixed with the shared `field_refusal` (#678).
- **Station contention with kesh.** Both projects share the heavy-job lock; mybibli waited hours on it until the project lead gave mybibli priority on 2026-11-11.
- **17-4 needed a second push.** A TypeScript error in a spec reached CI because `npx tsc --noEmit` was not in the local gates. When a spec changes, it must be.

## 4. Error-message review (Foundation Rule #9)

Sampled from `git diff v1.26.0..main -- locales/en.yml`:

| Key | Kind | Verdict |
|---|---|---|
| `error.isbn.invalid_format` ("Not an ISBN — expected 10 or 13 digits, e.g. …") | field hint | Conforms: terse, states the shape. |
| `error.isbn.invalid_checksum`, `error.upc.invalid_checksum` ("… the check digit does not match — check for a typo") | field hint | Conforms; the short "check for a typo" tail is tolerable in a field hint. |
| `error.upc.too_long`, `error.upc.isbn10` | field hint | Conform: one sentence, the bound or the right field named. |
| `feedback.code_unsupported` | operation | Conforms, and fixes the worst message of the epic: what (not recognised) → why (the accepted shapes) → what to do ("New title"). |
| `feedback.title_page_title_gone` | conflict | Conforms (what → why → what to do). |
| `empty.title_id_unknown_body`, `empty.title_id_trash_body` | operation | Conform; the Trash variant names who can restore it. |
| `scan.irregular_*` + `irregular_action_scan` / `irregular_action_form` | warning | Conform; the reason and the action are now split so the form and the scan each give the right next step. |
| `error.isbn.already_used` ("Another title already uses this ISBN — refusing to create a duplicate") | conflict | **Does not conform.** Phrased for creation, while the edit form creates nothing (#679 item 7), and it names no next step or link to the other title (#669 item 7). |

Also open: `error.title.required` and `error.media_type.invalid` still reach the edit form as a generic "Server error (400)" (#679 item 6; the client prevents both in practice).
