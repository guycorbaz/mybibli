## 2. What went well

- **The first reading of real logs paid off.** A bug and a CR came straight from it, including the 9-digit code whose lost `X` the check digit gave away.
- **Independent review earned its cost again.** It found a proposal shown with no target in the queue (16-3), a disconnect that freed the encode permit under a running decode (16-4), and an E2E helper that read the whole home page (16-5).
- **Rule #20 kept the decisions small.** Listed shapes made both the inconsistent price and the irregular code easy to test and to explain.
- **A stacked local branch per story** kept the one-push-per-story rule while waiting for CI, at the cost of a rebase per merge.
- **The shared station lock held.** Kesh and mybibli alternated all day with no coordination beyond it.

## 3. What did not go well

- **A full `cargo test` was killed by oomd at 12:27** (scope at 9.5 GB, pressure 62 %). Worse, my summary line was blank instead of red: the pipeline hid the kill, and only reading the empty count caught it. Full logs now go to a file, with the exit code printed.
- **A regression test written for a review finding proved nothing.** The first test of the disconnect case would have passed on the old code; the second review caught it, and it now holds the key lock to hit the exact window.
- **A fixed-ISBN spec cannot be rerun on the same database** (`mcp-cover-proposal`), which briefly read as a failure. It is an old pattern, not new debt.
- **A late change is costly.** Making the thresholds configurable after the gates had started meant stopping them and running them again. It was the right change; asking at planning whether a bound should be configurable would have avoided it.
