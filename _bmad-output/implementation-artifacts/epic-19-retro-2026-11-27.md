## 2. What went well

- **The backup feature is complete in one epic**: write, schedule, rotate, restore, recover at boot, check covers, document. NFR49 is covered by a round-trip test. The smoke test (19-10) drives the whole loop from a blank browser.
- **Security caught before release.** Review found live session tokens in the backup file twice: in `sessions` (19-6 M2) and in `pending_metadata_updates.session_token` (pass 2). The lead decided, and both are now out of the file, with a test that searches `database.sql` for a token.
- **Practice A3 held for copy.** In 19-1 and 19-3 to 19-9, every refusal and user-visible line was a numbered decision, approved before the first review. No review pass reopened approved copy. The lead could answer in one word ("A", "as proposed"). 19-8 alone had D1–D13 approved in one message.
- **19-2 made the suite trustworthy.** Three full runs had 0 flaky tests. `--repeat-each=10` over the riskiest specs passed 310/310. A flaky test now fails CI. The later stories all ended with "0 flaky" on full runs (486 → 523 tests).
- **Each restore failure has a defined outcome**: refusal, rollback or stuck, each with its copy. They are tested by a debug-build panic hook, never by a sleep. Review drove most of this (19-8 M1–M3, M-1).
- **Faster heavy builds (#717).** One integration binary and the BuildKit cache made the full Rust suite fit the memory guard. It was never killed this epic. Compare four kills in epic 18.
- **Accessible names became one app-wide rule** (#734, CLAUDE.md, a `starts_with` unit test) instead of a per-story finding.

## 3. What did not go well

- **Product decisions still surfaced in review, despite A3.** A3 settled the copy, but not every behaviour:
  - 19-3 D9: reuse of a trashed label was replaced by a refusal after review pass 2. A third pass followed.
  - 19-6 M2: session tokens in the file.
  - 19-7 M: a forward clock jump emptied the history. Retention became configurable and is counted over backup days.
  - 19-9 (b): the wrong-database guard was first approved as a ratio. The same day it proved it would block the real library, because purged titles leave orphans (#744). It was replaced by "an orphan id never handed out".
  - That replacement has a known false positive, found only in the documentation review (19-11 M3): a cover downloaded while a backup was being written blocks the repair after that backup is restored. It is documented, not fixed.
  - Each of these cost a pass and a message to the lead. What they have in common: secrets in a written file, clocks, and a guard never measured against the real library.
- **The documentation took four review passes on copy-paste commands** (19-11): 5 Medium findings, all in shell commands.
  - `-p"$MYSQL_ROOT_PASSWORD"` was expanded by the host shell.
  - Root-owned `0600` files need `sudo`.
  - A `DROP DATABASE` could run after a failed check.
  - A chain stopped at `cp` when there were no covers.
  - None of these commands had been run before review.
- **CI flakes and breaks from tests sharing state with other tests:**
  - #738: a Low deferred in 19-7's pass 2 (#733 item 1, the scheduled rotation's `now` taken before the write) became a CI flake on PR #736 within hours.
  - `tests/admin_audit_fk_set_null.rs` read `information_schema` with no schema filter. A parallel `#[sqlx::test]` database still mid-migration answered (1eadb88c). **The same shape remains** in `tests/api_key_revocation_lock_scope.rs:176` (`PROCESSLIST` without `DB = DATABASE()`).
  - `tests/backup_restore.rs` hard-coded "the newest migration". It broke when 20-4 added one (aae1eedd), a hidden coupling between the two epics. The fix still lists one migration by name and guards against a newer one.
- **Local tooling traps:**
  - `/tmp` is a RAM tmpfs: cargo targets of worktrees there compete with the build for memory. They moved to `~/devel/.wt-targets`.
  - #735: the shared BuildKit cargo cache served a binary built from another worktree, so a local E2E gate could run against code that is not the branch's. Every E2E gate since has rebuilt with `--no-cache`, which costs minutes per run.
- **A 500 lived unseen in the Trash search** (#750). No test typed a name into `#search-trash`. It was found while writing 19-9's E2E, fixed the same evening (#751) with a Rust and an E2E regression test.
- **Long review loops on the large stories**: 19-2 (4 passes, 6 Medium), 19-3 (4, 3), 19-8 (3, 4), 19-11 (5, 5). Story sizes were uneven: 19-8 and 19-9 each carried a dozen decisions.
- **Lows keep piling up**: ten new `type:code-review-finding` issues this epic, on top of #697–#704. None is urgent, but nothing is scheduled to drain them.

## 5. Error-message review (Foundation Rule #9)

Sample: every `error.*` key added or changed since `dea81f4` (`git diff dea81f4..main -- locales/en.yml locales/fr.yml`), plus the refusals of this epic that live outside `error.*`. They were checked against [`docs/error-message-style.md`](../../docs/error-message-style.md).

| Key | Kind | Verdict |
|---|---|---|
| `error.backup.folder_missing`, `folder_not_writable`, `already_running`, `failed` | operation | Conforms: what, then why, then what to do. They point to the manual. |
| `error.restore.damaged`, `no_sidecar`, `newer`, `not_readable`, `busy`, `bulk_running`, `drain_timed_out` | operation | Conforms. "Nothing was changed" is said each time, which is good for a destructive action. |
| `error.restore.safety_failed` | operation | Conforms. `%{reason}` is a localized backup error, never raw text (`RestoreError::localized`). The composed message is long. |
| `error.restore.gone` ("This backup is no longer in the folder. Nothing was changed.") | operation | **Breaks the guide:** it says what happened but gives no next step ("Reload the list, then choose another backup"). |
| `error.restore.not_a_backup` | operation | **Breaks the guide:** no why and no next step. It needs a reason ("its name or content is not a mybibli backup") and an action ("choose another file"). |
| `error.system.backup_interval_invalid`, `backup_retention_invalid` | field | Conforms: terse, with the bound. |
| `error.isbn.already_used` | field/conflict | Conforms: it names the title and gives the action. |
| `error.user.username_taken`, `version_mismatch` | conflict | Conforms (reworded in 19-4). |
| `error.reference_data.name_taken`, `version_mismatch`, `invalid_version` | conflict | Conforms (epic 18 Q2 answered). |
| `error.reference_data.node_type_name_too_long_for_cascade` | field | Conforms. The internal table name is gone. |
| `feedback.volume_label_in_trash` (outside `error.*`) | operation | Conforms. |
| `admin.trash.restore_contributor_name_taken` | conflict | Conforms. |
| `contributor.error.name_taken` ("Another contributor already has this name.") | conflict | **Breaks the guide.** It is an `AppError::BadRequest` from the rename, which lands in the feedback list, not next to a field. It says neither that nothing was saved nor what to do. Its sibling `restore_contributor_name_taken` does both. |
| `admin.covers.unreadable`, `unmounted`, `another_database`, `repair.failed`, `repair.stopped` | operation | Conforms. |
| `maintenance.text`, `maintenance.stuck` | system | Conforms. |
| `errors.server_error_retry` (unchanged, now quoted in the manual for the reverse-proxy 504) | fallback | Still shows an HTTP code. It was accepted as a last resort in the epic 18 retro and is now quoted on purpose in chapter 7. |
