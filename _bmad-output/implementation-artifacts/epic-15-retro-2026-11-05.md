## 2. What went well

- **The review found real defects every round, and old ones too.** 15-5: an acceptance locked the title row through a `FOR UPDATE` on a join, and a removed list price stayed in the rejection key. 15-6: an omnibus counted once per position in the per-series figures — a bug the CR #243 totals had carried since v1.5.0 — and the per-currency totals counted volumes of deleted titles, contrary to the page's own intro. All fixed with regression tests.
- **axe in the E2E caught an empty table header** before review.
- **Positive shapes held** (Rule #20): amounts with more than two decimals are refused, never rounded; a currency other than the default is refused, never converted; skill names are refused, never lowercased.
- **New logic in new modules.** `proposal_edit.rs` and `proposal_review.rs` (≈ 1 800 lines) only gained dispatch arms; every file stays under 2 000 lines.

## 3. What did not go well

- **Memory.** The 2026-11-04 session died at 21:48 (systemd-oomd killed GNOME Shell at 56 % pressure) during 15-3; a full `cargo test` later hit the 10 GB cap twice. Fixed for the rest of the epic: one compile job, line-table debug info (peak ≈ 5 GB), a pressure watchdog, and a station-wide lock shared with the kesh sessions (`/tmp/station-heavy.lock`). No crash since.
- **A second session worked in the same tree** after the crash; it was stopped by the project lead.
- **Two E2E specs were first written against library-wide counts** on the shared DB (flaky under parallel specs); the 15-6 review caught it — they now assert only on rows they create (their own series).
- **Lock scope still needs a reviewer's eye:** a locking read joined to `titles` (15-5) and the next-key lock on the neighbouring series' tomes (15-4, #627) were both found in review, not in design.

## 4. Error-message review (Foundation Rule #9)

Sampled: `error.mcp_skills.*` (field hints terse; `name_taken`, `name_in_trash*`, `stale`, `gone` follow "What happened → Why → What you can do"), `admin_system.time_zone_invalid`, the new `proposals.stale_why_*` (series changed, tome changed, below positions, value changed, purchase price set, currency changed, volume gone) and `proposals.edit_error_below_positions`.
