## 2. What went well

- **The dependency review paid for itself before any upgrade.** It found the audit red behind two ignores, the four *unsound* warnings, a CI on an end-of-life Node, and three build images following `latest` — all closed in one day.
- **Upgrading found real defects.** axe 4.14 revealed a WCAG 2.5.3 failure in the sidebar (18-1); fixing #526 revealed that, since polish-1, every `AppError` message had been dropped by HTMX and replaced by "Server error (N)" on every page (18-5).
- **Working in parallel with the CI** (project lead's decision, mid-epic): 18-5, 18-6 and 18-7 were developed while the previous story's CI ran, with no push before the merge. About an hour saved, no conflict beyond one `sprint-status.yaml` header line.
- **Regression proven before claiming a fix.** 18-4's integration test was run against the old endpoint and failed with exactly 25 names.
- **Station coordination with kesh worked**: messages before heavy series, kesh lent its second mem-guard slot, the Playwright browser-cache incident was settled the same hour.

## 3. What did not go well

- **A first fix in 18-5 created four regressions, caught only by review.** Opting AppError answers into the HTMX swap (`csrf.js`, `isError = false`) made errors look like successes: an admin "Add" refused closed its slot and cleared the name, a scan refused lost its code and left the duplicate guard armed, a failing `hx-push-url` would enter the history. The E2E suite stayed green because no spec exercised those paths with a real AppError. Replaced by inserting the server's entry from the error handler, HTMX keeping the response an error.
- **A test deleted by mistake (18-1).** A scripted edit of the neighbouring unit test removed `isbn10_to_isbn13_converts_production_examples`; all three reviewers caught it. Scripted multi-line edits need a diff read before commit.
- **The full Rust suite was killed four times** (oomd or the 10 G cap, at link time of the ~90 test binaries), even with kesh's slot freed. The light build (`--no-run` on one job, `line-tables-only` debug info, then the run) passed every time; it is now the default on the workstation.
- **#528 bit a new spec.** `api-series.spec.ts` sorted before the specs that assume no series exists and broke five tests; renamed `series-api.spec.ts`. The ordering convention is fragile and #528 is still open.
- **Scope grew in 18-5** (an app-wide JS change and a contrast fix on ten buttons), each recorded as a decision; the story was the longest of the epic.
- **A GitHub run stayed "queued" for 13 h** (planning PR) and could not be cancelled or deleted; re-triggered by close/reopen.

## 4. Error-message review (Foundation Rule #9)

No error key added or changed this epic (the only locale change is the screen-reader count `nav.proposals_pending_sr`). But 18-5 makes every server error message visible where the generic line used to stand, so the copy users now read deserves a look:

| Key | Kind | Verdict |
|---|---|---|
| `error.not_found` ("We couldn't find what you were looking for — it may have been moved or deleted.") | operation | Conforms: what → why; the next step (go back, reload) is implicit. |
| `error.internal` / AppError Internal ("Something went wrong on our end. Please try again; if the problem continues, contact your administrator.") | system | Conforms. |
| `admin.reference_data.name_taken` ("'%{name}' already exists") | conflict | **Does not conform**: what only; no "choose another name or reactivate". Now visible (before: "Server error (409)"). |
| `errors.server_error_retry` ("Server error (%{status}) — please try again.") | fallback | Still shown for non-AppError failures (proxy, network-level); contains an HTTP code (Rule #9). Acceptable as a last resort, now rare. |
