# mybibli Roadmap

Living plan for what ships next. The version slots are intentional, the
order is broadly stable, and the dates are deliberately absent — mybibli
is a side-project; we ship versions when they're ready, not when a
quarter ends.

The companion site at
[guycorbaz.github.io/mybibli/roadmap.html](https://guycorbaz.github.io/mybibli/roadmap.html)
gives the marketing-friendly view of the same plan. This file is the
canonical, complete one — including the patch-line maintenance policy
and the tech-debt parking lot.

## Versioning policy

mybibli follows [Semantic Versioning](https://semver.org/) 2.0.

- **Patch releases (`1.1.x`)** — bug fixes and known-failure
  resolutions only. No new features land on a patch line, no breaking
  changes, no schema migrations beyond what the fix strictly needs.
  Routine `docker compose pull && docker compose up -d` is always
  enough.
- **Minor releases (`1.2.0`, `1.3.0`, …)** — bundles of new features
  grouped by theme. Backwards-compatible; may ship additive schema
  migrations. The roadmap below is structured around these minors.
- **Major releases (`2.0.0`, …)** — reserved for breaking changes:
  schema migrations that drop columns, route renames, env-var removals.
  None planned at the time of writing — the
  [#206](https://github.com/guycorbaz/mybibli/issues/206) classification
  refactor is the only candidate, and even that may land on a minor if
  we find a backwards-compatible path.

## v1.8.6 — 2-issue tech-debt closure *(shipped)*

A tech-debt patch on v1.8.5 (shipped 2026-06-04). No user-facing behavior change; no operator action required. The two issues are coupled — #398 is the enabler for #386.

- [#398](https://github.com/guycorbaz/mybibli/issues/398) — **Embed `BaseContextFields` as a single `base` field.** Page-template structs flattened the ~20 shared base-context fields (`lang`, `role`, `csrf_token`, `nav_*`, …) one by one — 23 struct definitions + 23 construction sites, so adding any document-wide field to `layouts/base.html` was a 23×2 edit. They now embed the context as one `base: BaseContextFields` field; `base.html` + `nav_bar.html` + the inline-form pages read it via Askama nested-field access (`{{ base.lang }}`). **Net −1000 LOC.** Adding a global field is now one line in the struct + one in `base_context()`. Standalone HTMX fragment/modal structs keep their own flat `csrf_token` (rendered by their own structs, never via `base.html`).
- [#386](https://github.com/guycorbaz/mybibli/issues/386) — **Server-rendered i18n bundle for client JS.** `static/js/*.js` carried hand-synced `{en: …, fr: …}` objects that drifted from `locales/*.yml` and never covered de/it. `utils::build_js_i18n_bundle()` now resolves the JS-needed strings in the request locale and `layouts/base.html` emits them as a `<script type="application/json" id="i18n-bundle">` data island (`< > &` escaped to `\uXXXX` so a translated value can't break out). The session-timeout toast was migrated as the proof-of-concept — it now localizes in de/it for free. A follow-up ([#403](https://github.com/guycorbaz/mybibli/issues/403)) tracks sweeping the remaining two JS modules (needs net-new de/it locale copy).

## v1.8.4 — 3-issue hardening patch *(shipped)*

Test-only — no app code touched.

## v1.8.3 — 5-issue closure patch *(shipped)*

A second consecutive open-issue-reduction patch on v1.8.2 (shipped 2026-05-31). Closes 5 open issues directly + 2 follow-ups filed for items that need a design pass.

- [#41](https://github.com/guycorbaz/mybibli/issues/41) — **Session resolver inconsistency cleanup.** Pre-fix `resolve_or_mint` returned a Session whose `user_id` was `Some(N)` while `role` was `Anonymous` (soft-deleted user case) OR a Session with `user_id: None` whose `token` still pointed at a live authenticated row (expired-auth case). The fix rewrites the inner logic as an explicit match on `(row.user_id, row.role.as_deref(), expired)`: the happy path stays, the two inconsistent shapes share a single cleanup branch that soft-deletes the orphan row and falls through to mint a fresh anonymous session, and the genuine-anonymous arm stays untouched. Four sqlx::test cases lock the matrix.
- [#20](https://github.com/guycorbaz/mybibli/issues/20) — **Windowed pagination on home /.** New `PaginatedList::windowed_pages()` returns at most 11 entries (first + last + current ± 3 + `Ellipsis` markers for gaps). The template's `{% for p in 1..=paginated.total_pages %}` walk becomes `{% for entry in paginated.windowed_pages() %}` with a `{% match entry %}` over `PageEntry::Page(p) | PageEntry::Ellipsis`. A 10 000-title catalog renders 11 anchors instead of 400, and `?page=999999` is clamped to the last-page view. Six unit tests on the matrix.
- [#37](https://github.com/guycorbaz/mybibli/issues/37) — **HX-Trigger csrf-rotated for long-lived tabs.** When the session resolver mints a fresh row (purge, soft-delete cleanup, expired-auth cleanup post-#41), `session_resolve_middleware` now emits `HX-Trigger: csrf-rotated` + a sibling `X-CSRF-Token-Rotated: <new-token>` header. `static/js/csrf.js`'s existing `htmx:beforeSwap` listener reads the sibling header and propagates the new token to `<meta name="csrf-token">` + every `_csrf_token` hidden input — so the next mutation carries the fresh token instead of 403'ing. Two-header shape (rather than JSON HX-Trigger payload) preserves comma-mergeability with the existing `csrf-rejected` / `validation-error` / `modal-close` triggers.
- [#23](https://github.com/guycorbaz/mybibli/issues/23) — **Metadata provider robustness, 5 of 8 sub-items.** Typed `MetadataError::RateLimited` variant replaces the `err_str.contains("429")` string match in `chain.rs`. `session_inactivity_timeout_hours = 0` is now refused (mirrors the sibling `_seconds` guard; a 0-second timeout silently logged everyone out on every request). `MetadataResult::normalize_empty_strings()` drops empty-string fields at the chain boundary so a sloppy upstream `Some("")` doesn't COALESCE empty into the DB column and displace `manually_edited_fields`-protected values. `reqwest::Client` reuse and the loan-retry-exhausted log were both already in place (audited + verified). [#384](https://github.com/guycorbaz/mybibli/issues/384) tracks the 3 sub-items that need design (per-provider timeout configurable, OL author resolution via `join_all`, UPC checksum validation).
- [#29](https://github.com/guycorbaz/mybibli/issues/29) — **i18n technical debt, 2 of 3 sub-items.** Swap `serde_yaml 0.9` (RUSTSEC-2024-0320, unmaintained) for `serde_yaml_ng 0.10` — dev-dep only, mechanical `serde_yaml::` → `serde_yaml_ng::` sweep. New `tests/locale_html_safety.rs` integration test walks every leaf String in `locales/{en,fr,de,it}.yml` and refuses entries that look like HTML tags (`<` + letter/`/`/`!`) or entity references (`&` + alphanumeric + `;` within 8 chars) — defense in depth against translator-introduced XSS in the `format!("…{}…", t!(…))` sites. Whitelist `ALLOWED_HTML_KEYS` covers the two pre-existing legitimate HTML strings. [#386](https://github.com/guycorbaz/mybibli/issues/386) tracks the JS↔YAML extraction sub-item (needs design discussion on per-page vs. document-wide JSON bundles).

## v1.8.1 — polish patch *(shipped)*

A focused polish patch on v1.8.0 (shipped 2026-05-30) bundling one production-surfaced bug and four code-quality cleanups:

- [#300](https://github.com/guycorbaz/mybibli/issues/300) — **Phantom-volume guard.** `current_title_id` is sticky in the session (set on every ISBN scan, never cleared), so scanning a fresh V-code for ANOTHER physical book without re-scanning its ISBN silently attached a new volume to the previous title. Fix: a UX-DR8 confirmation modal returned when the active title already has ≥1 volume — Confirm bypasses the guard for the legitimate multi-copy flow, Cancel discards the scan. Surfaced pre-existing parallel-state pollution in 6 spec files which switched to per-test unique ISBNs.

Direct nav to `/title/999999` etc. no longer renders a styleless fragment on a blank page. HTMX requests pass through untouched.
- [#19](https://github.com/guycorbaz/mybibli/issues/19) — **Stable `is_primary` flag for the author role.** Three SQL queries hardcoded `cr.name = 'Auteur'` to promote the author role above other contributor roles. The admin reference-data CRUD (story 8-4) lets an operator rename a row at any time, which would silently break the author-first sort. New `is_primary BOOLEAN` column flagged on the seeded 'Auteur' row + queries switched to `cr.is_primary` — rename-resilient.
- [#87](https://github.com/guycorbaz/mybibli/issues/87) — **Per-target OOB swap mode** (replace/append) on `OobUpdate`. Default `Replace` preserves the project-wide pattern; `Append` opt-in emits `hx-swap-oob="beforeend"` so multi-action saves (e.g. the provider-keys form updating Google Books + OMDb + TMDb in one submit) can stack their per-sub-action feedbacks.
- [#18](https://github.com/guycorbaz/mybibli/issues/18) **aria-sort sub-item** — `aria-sort="ascending"|"descending"|"none"` added to the 5 sortable home-table column headers (title / primary_contributor / genre_name / dewey_code / volume_count) so screen-reader users hear which column is sorted. The two leftover sub-items (i18n the hardcoded "Active filter:" / "Filter by:" aria-label strings; re-enable the axe-core `color-contrast` rule in the 3 catalog specs after bumping placeholder contrast) are tracked in [#374](https://github.com/guycorbaz/mybibli/issues/374).

## v1.8.0 — "Covers, honestly" *(shipped)*

The seventh themed minor, born from the structural cover-miss gap diagnosed on the production NAS ([#333](https://github.com/guycorbaz/mybibli/issues/333) closed wontfix): ~73/147 titles will never get a cover from any free provider because the dominant FR/CH/DE trade & academic publishers (Dunod, Eyrolles, Slatkine, Mardaga, Kana, Casterman) are indexed by neither Google Books nor Open Library Covers. The pivot: stop chasing providers, make the manual-upload path discoverable and honest. Bundled with the completion of the internal `base_context()` refactor begun in v1.7.11.

- [#108](https://github.com/guycorbaz/mybibli/issues/108) — **Shared TitleCard partial.** The title-card markup (cover + title + author + volume badge) extracted into one Askama partial, removing the 3-site duplication across the home grid / recent-cataloged / recent-added surfaces (and the Rust HTMX search fragment).
- [#355](https://github.com/guycorbaz/mybibli/issues/355) — **"Titles without cover" home filter chip** (Librarian+). Lists titles with `cover_image_url IS NULL OR ''` so a librarian can walk them one by one. Unlike the bulk-refetch predicate it intentionally omits the ISBN/ISSN/UPC clause — identifier-less titles can never be auto-fetched, so they most need the manual path. Mirrors the #279 / #205 chip pattern; no schema, no migration.
- [#350](https://github.com/guycorbaz/mybibli/issues/350) — **Manual cover-upload affordance made visible.** `/title/:id` shows a prominent "Upload a cover" CTA plus a one-line explainer about the publisher gap when a title has no cover (a modest replace-link when it does); the admin Health tab links to the no-cover review list after a bulk re-fetch; the user manual (EN + FR, ch. 5) documents the gap honestly.
