{# LoanStatusBadge component (story 9-8 AC4). Renders the role-aware loan-status row for the volume-detail page (and any future caller — title-detail volume list, search volume rows, etc.). Two render variants based on `role`: - **Anonymous**: "On loan since {date}" — NO borrower name, NO /borrower/ link. Privacy-sensitive per FR59 (the SQL query layer also narrows the projection — see two-layer defense in LoanModel::active_loan_summary_for_volume). - **Librarian/Admin**: "On loan to since {date}" — borrower name is rendered as a plain link to /borrower/{id}. The handler builds 3 separate i18n strings (label_anonymous + label_prefix + label_suffix); the macro renders the link between the prefix and suffix. This avoids template-side string-splitting on an interpolated label and keeps the macro CSP-clean. Defense-in-depth: even if a future caller passes role="librarian" without populating borrower fields, the macro falls through to the anonymous variant rather than panicking on a None unwrap. CSP-clean — Tailwind utility classes only, no inline styles, no event handlers. The amber palette mirrors the existing "not_shelved" badge in volume_detail.html — locks the "consistent unavailability cue" UX contract. #} {%- macro badge(role, label_field, label_anonymous, label_prefix, label_suffix, borrower_id, borrower_name, view_borrower_aria) -%} {# `view_borrower_aria` parameter retained for API stability — currently unused because the link's visible text (the borrower's name) is already a meaningful accessible name; adding an `aria-label` would hijack that for screen readers AND break Playwright's role-by-name lookup (CI catch on PR #124 — `getByRole("link", { name: borrower })` found zero matches when `aria-label="View borrower profile"` was present). The parameter stays so future callers can opt back in with a per-call accessible-name override if needed. #}
