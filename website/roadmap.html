Roadmap

Shipped, and shipping next.

mybibli reached v1.0 after ten epics of foundational work, and is in production on the household NAS that drove the project. Beyond v1, every release is a focused theme — see what's coming next, or scroll down for what already shipped. Pre-built Docker images on Docker Hub; everything tracked openly as GitHub issues.

What's next

Coming up.

Planned releases, in roughly the order they will ship. Themes are stable, dates are not — mybibli is a side-project and ships when ready. Each version is bundled around one coherent user benefit. The full plan, including the tech-debt parking lot, lives in ROADMAP.md.

  1. v1.2

    See what you own, find it faster

    Planned

    A polish round around discoverability. Several small wins that together make daily browsing noticeably nicer.

    • Sort series and shelf views by Dewey code.
    • Show the Dewey code right next to the genre on the title page.
    • Filter the catalog by "uncategorized" titles in one click.
    • Collapse the Locations tree, with a spinner on the slower bulk metadata re-fetch.
    • An admin action to re-fetch all missing covers in one go.

    Tracked on GitHub: #235 · #236 · #205 · #200 · #215 · #214

  2. v1.3

    Plan your next purchase

    Planned

    A wish list lives next to your catalog. Scan an ISBN at home, browse it on your phone in the bookstore, print it to PDF if you prefer paper. When you actually buy the book and scan it in, mybibli quietly clears the wish list entry.

    • Add books by ISBN (with metadata) or free-form title (when you only have a name).
    • Bookstore-friendly mobile view + printable PDF export.
    • Auto-remove from the wish list on catalog scan match.
    • Per-volume list (V-codes and shelf locations) on the title page.

    Tracked on GitHub: #242 · #209

  3. v1.4

    Open the catalog to your AI

    Planned

    A clean JSON HTTP API behind admin-issued keys, with two coexisting access levels: read-only and read-write. Built for an AI assistant to read your catalog and propose classifications (Dewey, genre, description), but works just as well for any homelab script.

    • Read-only or read-write API keys, issued and revoked from the admin panel.
    • JSON endpoints for titles, contributors, volumes, locations, series.
    • Write access narrowly scoped to classification fields — your AI can suggest, not delete.
    • Two keys can be active at once — one for the AI, one for a custom script.

    Tracked on GitHub: #241

  4. v1.5

    Know what your collection is worth

    Planned

    Track purchase price and current value per volume — handy for collector BD, signed editions, and the insurance form nobody wants to fill out from scratch.

    • Two optional fields per volume: purchase price + current value, with currency.
    • Aggregated totals: whole library, per genre, per series.
    • Opt-in dashboard indicator — values stay invisible unless you turn them on.

    Tracked on GitHub: #243

  5. v1.6

    Audit your shelves

    Planned

    A guided audit workflow built around a persistent "to check" flag. Mark a shelf or a search-result set, walk the rows physically, clear the flag as you verify each volume. What's left at the end is what needs attention.

    • Bulk-mark every volume on a shelf — or selected volumes from any search result.
    • Dedicated filter view for the audit pass; mobile-friendly so you walk with your phone.
    • The flag stays put until you clear it manually — no auto-clear, by design.

    Tracked on GitHub: #237

  6. v2.0 candidate

    Classification, reinvented

    Exploring

    Today the "genre" field tries to be two things at once: the catalog source's idea of a section, and the owner's manual classification. v2 candidate splits them — keep Dewey for the standards-based axis, treat genre as a free-form owner-side label, and stop the auto-fetch from ever touching either.

    • Splits a longstanding entanglement that surfaced in v1.1.8's genre_id fix.
    • Will land on a minor version if a backwards-compatible path is found, on v2.0 otherwise.

    Tracked on GitHub: #206

  11. Milestone

    v1.1.9 — in production

    ✓ Live

    mybibli has been live on the household NAS that drove the project since v1.1.1 (2026-05-14). v1.1.9 is the current release — closes a longstanding UX bug (issue #238): clicking Save on a title where any numeric field (page count, track count, total duration, issue number) was empty used to fail silently with an HTTP 422 visible only in the browser console; the four numeric form fields now treat an empty input as "not provided" instead of refusing to deserialize. It follows v1.1.8 (stop tracking genre_id in manually_edited_fields + first illustrations — issue #232), v1.1.7 (Open Library Covers fallback on the Re-fetch path — issue #228), v1.1.6 (same fallback on the fresh-scan path — issue #225), v1.1.5 (defensive genre fallback for no-metadata scans, modal-Confirm header hardening, Google Books config walkthrough), v1.1.4 (cover JPGs persisted across container upgrades via the mybibli_covers named volume — issue #213) and v1.1.3 (home-page layout reorder, clickable locations tree). Pre-built Docker images on Docker Hub at gcorbaz/mybibli — :1.1.9 + :latest. Honor the 1.1.0 minimum install floor (seed-gate + audit trio); earlier tags are removed.
