Roadmap

Shipped, and shipping next.

Beyond v1, every release is a focused theme — see what's coming next, or scroll down for what already shipped. Pre-built Docker images on Docker Hub; everything tracked openly as GitHub issues.

What's next

Coming up.

Planned releases, in roughly the order they will ship. Themes are stable, dates are not — mybibli is a side-project and ships when ready. Each version is bundled around one coherent user benefit. The full plan, including the tech-debt parking lot, lives in ROADMAP.md.

  1. Backlog

    Polish & community CRs

    Unscheduled

    The originally-planned v1.1–v1.7 build is complete and v1.8 closed out the themed minors. mybibli is now in GH-issue-driven polish mode: v1.9.0 was the first issue-driven feature minor (saved custom searches over the home filter/sort surface, per-provider metadata-timeout overrides in the admin System tab, the admin log-level form’s stale-version 409 fixed, and HTTP transport-crate debug chatter capped), followed by v1.10.0 — a 30-second undo of the last scan action (#9) — then v1.11.0, a four-issue bundle straight from a production-log review (persistent session cookie + configurable timeout #418, bulk cover-refetch pacing/back-off/summary #419, auto-purge unblocked #416, log-noise fix #417) — then v1.12.0 (same day): BnF Couvertures + Inventaire.io cover sources (#427) and the highest-used-label helper for printing sheets (#428) — then v1.13.0 (2026-07-24): six UNIMARC-aligned cataloging fields captured from the BnF at scan time — then v1.14.0 (2026-07-28): three scan-flow fixes (volume labels attaching to the previous title #440, a misleading not-found on a deleted active title #441, labels locked after deletion #442) plus Library of Congress MARC 21 records filling the UNIMARC fields for English-language books #439. The latest is v1.15.0 (2026-08-13), a four-issue bundle from an August production-log review: titles now record and show which library described them (#202), faint secondary text raised above the AA contrast floor (#424), a third retry tier so bulk metadata runs stop abandoning throttled titles (#419), and a shorter build commit in the startup log (#449); one additive migration. Superseded detail on v1.13.0: six UNIMARC-aligned cataloging fields captured from the BnF at scan time and shown on the title page, with a Health-tab backfill action for existing catalogs (#389) and a per-title cataloging log summary (#434); record import/export is queued as #436. New CRs are queued here until a coherent theme emerges or enough land to bundle into the next minor; patches ship independently for production bugs.   2. v2.0 candidate

    Classification, reinvented

    Exploring

    Today the "genre" field tries to be two things at once: the catalog source's idea of a section, and the owner's manual classification. v2 candidate splits them — keep Dewey for the standards-based axis, treat genre as a free-form owner-side label, and stop the auto-fetch from ever touching either.

    • Splits a longstanding entanglement that surfaced in v1.1.8's genre_id fix.
    • Will land on a minor version if a backwards-compatible path is found, on v2.0 otherwise.

    Tracked on GitHub: #206

The ten epics

Each one ships behind a draft PR per story, gated by green CI. Each one ends with a retrospective.

    ✓ Done

    Project skeleton, scan field, title CRUD with ISBN scanning, volume management, contributor management, search, async metadata fetch, login. The foundation.

  2. Epic 2

    I know where my books are

    ✓ Done

    Configurable storage-location hierarchy, scan-to-shelve workflow, browse a shelf's contents, contextual guidance.

  3. Epic 3

    All my media types

    ✓ Done

  4. Epic 4

    ✓ Done

  5. Epic 5

    ✓ Done

  11. Milestone

    v1.1 → v1.12 — the production line

    ✓ Live

    mybibli has been live on the household NAS that drove the project since v1.1.1 (2026-05-14). Seven themed minors (v1.2 "See what you own, find it faster" → v1.8 "Covers, honestly") delivered the original feature roadmap — browse & find, wishlist, the JSON HTTP API, valuation & stats, catalog hygiene, German/Italian locales + runtime logging, honest cover handling — each followed by a production-driven patch train. The current release is v1.15.0 — metadata provenance on the title page (#202), light-mode contrast raised to the AA threshold (#424), a third retry tier for bulk metadata runs (#419), and a shorter build commit in the log (#449). It follows v1.14.0 — three scan-flow fixes (#440, #441, #442) and Library of Congress MARC 21 coverage for English-language books (#439) — and v1.13.0 — six UNIMARC-aligned cataloging fields captured automatically from the BnF and a Health-tab backfill action for existing catalogs (#389), plus a per-title cataloging log summary (#434). It follows v1.12.0 — two new cover sources (BnF legal-deposit scans + Inventaire.io, #427) recovering about half of the previously unfindable French/Swiss covers, and a label-printing helper (#428) — and same-day v1.11.0 — a four-issue bundle from a production-log review: sessions that survive a tablet screen-lock (#418), a bulk cover-refetch that paces itself and reports its results (#419), the daily auto-purge unblocked (#416), and quieter logs (#417). It follows v1.10.0 — the scanner Undo button (#9) — and v1.9 — the v1.9.0 feature minor (saved searches, per-provider metadata timeouts, logging fixes) plus a same-day v1.9.1 patch localizing the last two client-side messages in German/Italian. Every release is documented on the GitHub releases page.
