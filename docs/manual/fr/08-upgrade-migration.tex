\chapter{Mise à jour et migration}
\label{ch:upgrade}

Les mises à jour de routine sont conçues pour être sûres.
L'exception est le saut 1.0.x → 1.1.0, un breaking change unique
documenté ci-dessous.

\section{Mises à jour de routine (1.y → 1.z)}

\begin{enumerate}
  \item Lisez les notes de version pour chaque version entre votre
        version courante et la cible.
  \item Prenez une \textbf{sauvegarde de base} fraîche
        (chapitre~\ref{ch:backup}).
  \item Mettez à jour le tag d'image dans
        \texttt{docker-compose.yml} (ou re-tirez \texttt{:latest}
        si vous suivez ce tag).
  \item Lancez \texttt{docker compose up -d}. Le nouveau conteneur
        boote, exécute les nouvelles migrations contre la base
        existante, et reprend le service.
  \item Surveillez les logs pour les erreurs de migration :
        \texttt{docker compose logs mybibli | grep -i migrate}.
\end{enumerate}

Les migrations sont append-only — les changements de schéma sont
forward-compatibles. Une installation 1.4 mise à jour en 1.5 garde
toutes les lignes de 1.4 et applique les nouvelles tables /
colonnes sur place.

\begin{tip}
Pour les installations homelab, le tag Docker \texttt{:latest} est
un défaut raisonnable. Pour des montages production
(bibliothèque communautaire, association), épinglez une version
explicite pour qu'un \texttt{pull} non surveillé n'amène pas une
release sur laquelle vous n'avez pas lu les notes.
\end{tip}

\section{Sauter des versions intermédiaires}

Passer d'une installation bien plus ancienne (1.3.x par exemple)
directement à la version courante est supporté et sûr pour la
base. Le moteur de migrations applique toutes les migrations
non encore appliquées dans l'ordre des timestamps au boot,
quelle que soit la distance sautée. Les migrations de schéma
sont purement additives — aucun \texttt{DROP COLUMN}, aucun
\texttt{DROP TABLE} dans aucune release — et les quatre
backfills de données existants (le seed CSRF token de 1.1.0,
le nettoyage \texttt{manually\_edited\_fields} de 1.1.8, etc.)
sont idempotents.

Ce qui reste valable sur un saut multi-versions :

\begin{itemize}
  \item \textbf{Sauvegardez avant la mise à jour.} Il n'y a pas
        de rollback automatique. Une migration qui échoue en
        cours d'exécution laisse la base dans un état
        incohérent ; la voie de récupération est la sauvegarde
        pré-mise à jour (chapitre~\ref{ch:backup}).
  \item \textbf{Les couvertures JPG pré-1.1.4 sont perdues.}
        Jusqu'à 1.1.4, le volume \texttt{mybibli\_covers}
        n'était pas déclaré ; les couvertures écrites avant
        cette version étaient perdues à chaque upgrade de
        conteneur. Sauter directement vers 1.7 ne les récupère
        pas — re-fetch via l'action admin \textbf{Bulk re-fetch
        missing covers} (ajoutée en 1.2) ou le bouton
        \textbf{Re-fetch metadata} par titre.
  \item \textbf{Le premier boot peut prendre quelques minutes.}
        Un saut qui exécute 20+ migrations contre un gros
        catalogue est silencieux côté UX — attendez que
        \texttt{/health} réponde avant de vous inquiéter.
\end{itemize}

Le saut 1.0.x → 1.1.0 est l'unique exception qui nécessite la
procédure dédiée ci-dessous.

\section{Le saut 1.0.x → 1.1.0}\label{sec:upgrade-1.1.0}

\begin{warning}
\textbf{Ceci est un breaking change unique.}\index{mise à jour 1.1.0}
Les installations 1.0.x sont sujettes au bug documenté dans
\href{https://github.com/guycorbaz/mybibli/issues/173}{\#173} :
les migrations seed créent les identifiants \texttt{admin/admin}
et \texttt{librarian/librarian} à chaque installation neuve, y
compris en production, et contournent silencieusement l'assistant
de première mise en service.
\end{warning}

Le chemin recommandé dépend de si votre installation 1.0.x détient
des données réelles :

\subsection*{Si votre installation 1.0.x est vide (aucun titre catalogué)}

Le chemin le plus simple : effacer la base et réinstaller en 1.1.0+.

\begin{enumerate}
  \item Arrêter la pile : \texttt{docker compose down}.
  \item Supprimer le volume de base :
        \texttt{docker volume rm mybibli\_mybibli\_db\_data}
        (ou l'équivalent sur votre hôte —
        \texttt{docker volume ls} les liste).
  \item Tirer l'image 1.1.0 : \texttt{docker compose pull}.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} si vous aviez épinglé une
        version antérieure.
  \item Démarrer : \texttt{docker compose up -d}.
  \item Ouvrir \texttt{/setup} et parcourir l'assistant.
\end{enumerate}

\subsection*{Si votre installation 1.0.x détient des données réelles}

\begin{enumerate}
  \item Prenez une sauvegarde de base (chapitre~\ref{ch:backup}).
  \item Prenez une sauvegarde covers + \texttt{.env}.
  \item Connectez-vous comme l'admin seedé et changez le mot de
        passe \emph{avant} la mise à jour. La mise à jour 1.1.0
        elle-même est sûre, mais la rotation ferme la dernière
        fenêtre pendant laquelle les identifiants par défaut
        pourraient fuiter.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} et lancer
        \texttt{docker compose up -d}.
  \item Le boot 1.1.0 détecte l'admin existant et n'active
        \emph{pas} l'assistant — l'admin avec mot de passe tourné
        reste l'admin actif.
\end{enumerate}

\subsection*{La nouvelle variable \texttt{MYBIBLI\_SEED\_DEV\_USERS}}

À partir de 1.1.0, la migration seed est gardée par
\texttt{MYBIBLI\_SEED\_DEV\_USERS}\index{MYBIBLI\_SEED\_DEV\_USERS}.
Le défaut est \texttt{0} (pas de seed). Ne la positionnez à
\texttt{1} que pour des flux de dev local ou des tests automatisés
— jamais en production. L'assistant de première mise en service
devient le chemin canonique d'onboarding.

\section{Lire les notes de version}

Chaque release mybibli publie une page GitHub Release avec :

\begin{itemize}
  \item un paragraphe résumant le changement ;
  \item l'impact migration (aucun / additif / breaking) ;
  \item un lien vers le diff contre le tag précédent ;
  \item les PDF de ce manuel (anglais + français) en pièce jointe
        une fois le build PDF de release câblé dans la CI.
\end{itemize}

Lisez les notes avant de mettre à jour. Les breaking changes
portent une étiquette \emph{Breaking} bien visible.

\section{Nouveautés de la 1.9.0}\label{sec:whats-new-1.9.0}

La version 1.9.0 regroupe les fonctionnalités et correctifs fusionnés
depuis la 1.8.6. \emph{Aucune action de l'opérateur requise} — l'unique
nouvelle migration de base de données s'applique automatiquement.
\texttt{docker compose pull \&\& docker compose up -d} de routine.

\begin{itemize}
  \item \textbf{\#367 \string— recherches enregistrées.} Une composition
        de recherche sur la page d'accueil (texte libre, filtre, colonne
        et sens de tri) peut désormais être enregistrée sous un nom et
        relancée en un clic depuis le menu \emph{Recherches enregistrées}
        à côté du contrôle de tri. Les entrées peuvent être renommées et
        supprimées depuis le même menu. Les recherches enregistrées sont
        partagées par toute l'instance. Voir la
        section~\ref{sec:saved-searches} du chapitre d'utilisation.
  \item \textbf{\#396 \string— délais métadonnées par fournisseur.} Le
        délai d'attente des consultations de métadonnées peut désormais
        être surchargé \emph{par fournisseur} depuis \texttt{/admin >
        Système > Fournisseurs de métadonnées} : un champ par fournisseur
        enregistré, vide = valeur globale par défaut. Donnez plus de
        marge à un fournisseur lent sans ralentir toute la chaîne.
        Appliqué au prochain scan \string— sans redémarrage.
  \item \textbf{\#406 \string— formulaire de niveau de journalisation
        réparé.} Enregistrer le niveau de journalisation depuis
        \texttt{/admin > Système} une seconde fois n'échoue plus
        silencieusement sur un conflit de version ; le basculement du
        filtre à chaud fonctionne désormais de façon fiable d'un
        enregistrement à l'autre.
  \item \textbf{\#405 \string— journaux debug plus silencieux.} Quand
        l'opérateur règle un niveau global \texttt{debug}, les
        bibliothèques de transport HTTP n'inondent plus le journal de
        bavardage de pool de connexions ; une directive explicite par
        bibliothèque garde la priorité si ce détail est nécessaire.
\end{itemize}

\section{Nouveautés de la 1.8.6}\label{sec:whats-new-1.8.6}

La version 1.8.6 est un correctif de dette technique interne fermant
deux issues sur la 1.8.5. \emph{Aucune action de l'opérateur requise, et
aucun changement visible dans le comportement de l'application.} Mise à
jour de routine \texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{\#398 \string— maintenabilité interne.} Chaque page
        complète partage désormais son contexte commun
        d'en-tête/navigation via une seule valeur regroupée au lieu de
        répéter une vingtaine de champs sur chaque page. Cela supprime
        environ mille lignes de code dupliqué et fait qu'un futur ajout
        d'interface valable sur tout le site devient une modification
        d'une ligne plutôt qu'une passe sur deux douzaines de pages.
        Aucun changement visible \string— mentionné pour être complet.
  \item \textbf{\#386 \string— préparation à des traductions plus
        complètes.} Les petits textes affichés par les scripts du
        navigateur (comme l'avertissement «~votre session va bientôt
        expirer~») sont maintenant transmis au navigateur déjà traduits
        pour la langue active, depuis les mêmes fichiers de traduction
        centraux que le reste de l'interface, au lieu d'une copie
        séparée maintenue à la main qui ne connaissait que l'anglais et
        le français. Conséquence directe~: cet avertissement de fin de
        session s'affiche désormais aussi en allemand et en italien.
\end{itemize}

\section{Nouveautés de la 1.8.5}\label{sec:whats-new-1.8.5}

La version 1.8.5 est un correctif de fermeture de trois issues sur la
1.8.4. \emph{Aucune action de l'opérateur requise.} Mise à jour de
routine \texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{\#10 \string— messages d'erreur plus clairs.} Le texte
        affiché lorsqu'une opération échoue a été réécrit dans un style
        en langage clair~: ce qui s'est passé, pourquoi, et ce que vous
        pouvez faire \string— sans code d'erreur, sans jargon technique,
        sans détail interne qui transparaît. La refonte couvre les
        quatre langues de l'interface (allemand, anglais, français,
        italien).
  \item \textbf{\#384 \string— recherches de métadonnées plus rapides et
        plus strictes.} Quand un titre compte plusieurs auteurs, leurs
        fiches sont désormais récupérées en parallèle depuis Open Library
        au lieu d'être traitées l'une après l'autre, ce qui accélère
        nettement les titres multi-auteurs. Un code-barres UPC-A scanné
        ou saisi est maintenant validé par sa somme de contrôle~: un code
        à 12 chiffres mal saisi est rejeté immédiatement plutôt que de
        déclencher une recherche infructueuse.
  \item \textbf{\#391 \string— maintenabilité interne.} Le code de
        l'onglet utilisateurs a été déplacé dans son propre module pour
        la maintenabilité. Aucun changement visible par l'utilisateur
        \string— mentionné pour être complet.
\end{itemize}

\section{Nouveautés de la 1.8.4}\label{sec:whats-new-1.8.4}

La version 1.8.4 ferme trois issues de durcissement et de qualité sur
la 1.8.3. \emph{Aucune action de l'opérateur requise}~; l'unique
migration de documentation s'applique automatiquement. Mise à jour de
routine \texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{\#21 \string— durcissement de la couche base de
        données.} Le pool de connexions définit désormais des délais
        d'acquisition et d'inactivité explicites~: une requête en
        attente sur un pool saturé échoue rapidement au lieu de rester
        bloquée, et un NAS inactif la nuit recycle les connexions
        périmées. Le point d'accès \texttt{/health} passe d'un simple
        témoin «~le processus tourne~» à une véritable sonde de
        disponibilité~: il exécute un \texttt{SELECT 1} et renvoie
        \texttt{503} quand la base est injoignable, pour qu'un
        moniteur externe (ou le \emph{healthcheck} du conteneur)
        distingue un processus vivant d'un processus ayant perdu sa
        base.
  \item \textbf{\#55 \string— durcissement de l'onglet utilisateurs.}
        Le paramètre de page de la liste des utilisateurs est désormais
        borné (une valeur \texttt{?page=} hostile ou accidentelle ne
        peut plus provoquer de débordement du calcul d'offset)~; tenter
        de désactiver son propre compte ou le dernier administrateur
        affiche maintenant un message correctement traduit plutôt
        qu'une clé interne~; et les formulaires de création/édition
        valident la longueur du nom d'utilisateur (3 à 255 caractères)
        en amont au lieu de laisser remonter une erreur de base de
        données.
  \item \textbf{\#22 \string— qualité interne de la suite de tests.}
        Une passe de consolidation de la suite de tests bout-en-bout
        (assistants de connexion et de recherche partagés, résolution
        déterministe des enregistrements, données de test uniques
        compatibles avec l'exécution parallèle). Aucun changement
        visible par l'utilisateur \string— mentionné pour être complet.
\end{itemize}

\section{Nouveautés de la 1.8.3}\label{sec:whats-new-1.8.3}

La version 1.8.3 est une deuxième session consécutive de fermeture
d'issues sur la 1.8.2, fermant cinq issues GitHub. \emph{Aucune
migration de schéma demandant une action de l'opérateur}~; mise à
jour de routine \texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{\#41 \string— cohérence du résolveur de session.}
        Quand un administrateur désactive un compte utilisateur
        pendant qu'il est en train de naviguer, ou quand une session
        authentifiée dépasse son délai d'inactivité, la ligne en
        base de données restait intacte et la Session en mémoire se
        retrouvait dans un demi-état (une identité authentifiée mais
        qui refusait l'authentification). Le résolveur supprime
        désormais en doux la ligne orpheline dans les deux cas et
        ouvre une nouvelle session anonyme~; la requête suivante voit
        un état cohérent.
  \item \textbf{\#20 \string— pagination plus courte sur la page
        d'accueil.} Auparavant tous les numéros de page de 1 à N
        étaient rendus. Sur un grand catalogue (10\,000 titres
        \string= 400 pages) cela remplissait la page de 400 ancres
        et rendait l'ordre de tabulation inutilisable. La navigation
        affiche désormais au maximum onze liens~: premier, dernier,
        la page courante \string± 3 et un \texttt{...} littéral
        quand un intervalle a été replié.
  \item \textbf{\#37 \string— les onglets ouverts depuis longtemps
        ne renvoient plus 403 après une rotation de session en
        arrière-plan.} Quand la tâche de purge des sessions
        anonymes (ou le nettoyage \#41) tournait, le jeton CSRF en
        mémoire dans l'onglet divergeait de celui stocké
        côté serveur~; la soumission de formulaire suivante échouait
        avec un retour \emph{session expirée}. Le serveur signale
        désormais la rotation sur sa prochaine réponse~; la couche
        JavaScript réécrit le jeton CSRF de la page sur place et la
        mutation suivante passe.
  \item \textbf{\#23 \string— robustesse des fournisseurs de
        métadonnées.} Une configuration de
        \texttt{session\_inactivity\_timeout\_hours = 0} (acceptée
        en silence avant) aurait déconnecté tout le monde à chaque
        requête~; le chargeur refuse maintenant zéro. La détection
        de limitation de débit (HTTP 429) côté fournisseur utilise
        un signal typé au lieu d'une recherche de motif dans le
        message d'erreur, et un futur changement de phrasé ne peut
        plus passer inaperçu. Une réponse en amont qui renvoie une
        chaîne vide pour un champ manquant n'écrase plus une vraie
        valeur en base.
  \item \textbf{\#29 \string— hygiène sécurité et i18n.} Remplacé la
        dépendance YAML non maintenue (\texttt{serde\_yaml} 0.9,
        bulletin RUSTSEC-2024-0320) par son fork activement maintenu
        (\texttt{serde\_yaml\_ng} 0.10). Nouvelle vérification
        d'intégration continue~: rejet de toute traduction qui
        introduirait accidentellement du HTML brut dans les fichiers
        de locale, fermant une surface latente d'attaque XSS.
\end{itemize}

\section{Nouveautés de la 1.8.2}\label{sec:whats-new-1.8.2}

La version 1.8.2 est une session ciblée de fermeture d'issues sur la
1.8.1, \emph{sans aucun changement visible côté utilisateur}. L'objectif
est de faire baisser la liste des issues ouvertes~: sept issues GitHub
fermées en un seul patch (\#151, \#365, \#370, \#374 directement, plus les
parents \#26, \#30 et \#18 via les issues porteuses). Aucune migration
de schéma, aucun changement de paramètres~; mise à jour de routine
\texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{\#151 \string— alignement spécification / implémentation
        de la barre de navigation.} Trois sources de planning divergeaient
        sur les liens visibles par les utilisateurs Anonymes. Le story
        9-18 avait déjà livré l'option A~; ce patch aligne la spécification
        UX et les critères d'acceptation de l'épopée 9.18 pour que les
        futurs lecteurs ne rouvrent pas le débat. Documentation uniquement.
  \item \textbf{\#365 \string— hygiène des jetons de session et CSRF.} La
        fonction qui génère les jetons de session était définie à trois
        endroits différents, avec des commentaires qui divergeaient
        subtilement. C'est maintenant une seule implémentation canonique.
        Même opération pour le générateur de jeton CSRF. Un piège latent
        dans le chemin d'extracteur \texttt{Session} (utilisé uniquement
        par les tests) qui renvoyait un jeton CSRF vide est refermé.
  \item \textbf{\#370 \string— variantes d'erreur typées.} Quand deux
        utilisateurs modifient le même enregistrement en parallèle, le
        message 409 résultant indique maintenant «~Un autre utilisateur
        vient de modifier ce \string<entité\string>~» (ou «~Ce
        \string<entité\string> vient d'être supprimé~» si la ligne a été
        soft-supprimée entre la lecture et l'écriture) au lieu d'un
        générique «~Cet enregistrement a été modifié par un autre
        utilisateur~». Nettoyage interne~: le constructeur du fragment
        FeedbackEntry sort d'un module de routes, la couche d'erreur
        n'en dépend plus.
  \item \textbf{\#374 \string— filets CI + accessibilité restante.} Deux
        nouveaux tests automatisés protègent le pipeline de release~:
        l'un reproduit le parseur Python qui extrait la version du
        Cargo.toml depuis le tag de release, l'autre rejoue toutes les
        migrations sur une base fraîche et vérifie que les données seed
        satisfont toujours les contraintes NOT NULL / unique / clés
        étrangères du schéma. Côté utilisateur, huit chaînes
        \texttt{aria-label} anglaises codées en dur sur les pastilles de
        filtre de la page d'accueil sont maintenant livrées dans les
        quatre langues d'interface, et les pages de formulaire du
        catalogue réactivent l'audit de contraste WCAG après un relèvement
        global de la couleur des placeholders.
\end{itemize}

\section{Nouveautés de la 1.8.1}\label{sec:whats-new-1.8.1}

La version 1.8.1 est un patch ciblé de polish sur la 1.8.0. Elle ferme un
bogue remonté en production et quatre nettoyages issus du queue de
revue. \emph{Aucune migration de schéma demandant une action de
l'opérateur}~; la migration qui ajoute la colonne \texttt{is\_primary} sur
\texttt{contributor\_roles} s'exécute automatiquement au démarrage. Mise
à jour de routine~: \texttt{docker compose pull \&\& docker compose
up -d}.

\begin{itemize}
  \item \textbf{\#300 \string— garde contre les volumes fantômes.} Un
        bogue subtil présent depuis la v1.0~: la session de catalogue
        garde le titre de la dernière ISBN scannée dans un emplacement
        \emph{titre courant} collant, jamais effacé. Si vous scanniez un
        V-code pour un autre livre physique sans d'abord re-scanner son
        ISBN, le nouveau volume était silencieusement rattaché au titre
        précédent \string— d'où des titres affichant deux ou trois
        volumes qu'on ne possède pas vraiment. Le correctif fait
        apparaître une modale de confirmation dès qu'on scanne un V-code
        pour un titre qui a déjà des volumes~: \emph{«~Ajouter un autre
        exemplaire de \string<titre\string>~?~»}. Cliquez \emph{Ajouter
        un exemplaire} pour le flux multi-exemplaires légitime~;
        \emph{Annuler} pour abandonner le scan et re-scanner d'abord
        l'ISBN du nouveau livre.
  \item \textbf{\#216 \string— pages d'erreur lisibles en navigation
        directe.} Jusqu'ici, naviguer directement vers une URL qui
        renvoie une erreur (p.~ex.\ un signet vers un titre supprimé)
        affichait le fragment de feedback sans style sur une page
        blanche. Un nouveau middleware enveloppe ces réponses dans une
        coque HTML minimale~: les erreurs en nav directe sont désormais
        lisibles avec un lien Accueil pour revenir. Les interactions
        HTMX dans l'app ne sont pas touchées.
  \item \textbf{\#19 \string— rôle auteur résilient au renommage.} Le
        tri auteur-d'abord sur les listes de contributeurs et la
        recherche d'auteur de la chaîne de métadonnées matchaient le nom
        littéral «~Auteur~», donc renommer le rôle depuis le panneau
        admin des données de référence cassait silencieusement les deux.
        Un nouveau marqueur \texttt{is\_primary} sur le rôle seedé
        remplace ce check par nom \string— renommez librement.
  \item \textbf{\#87 \string— mode de swap OOB par cible.} Les
        formulaires qui mettent à jour plusieurs choses en une seule
        soumission (p.~ex.\ le formulaire des clés providers mettant à
        jour Google Books, OMDb et TMDb ensemble) peuvent désormais
        empiler leurs feedbacks par sous-action au lieu de les écraser.
        Le comportement par défaut est inchangé.
  \item \textbf{\#18 \string— les en-têtes de colonnes triables
        annoncent l'état de tri.} Les cinq colonnes triables du tableau
        d'accueil portent désormais l'attribut \texttt{aria-sort}, pour
        que les utilisateurs de lecteur d'écran entendent quelle colonne
        est triée et dans quel sens.
\end{itemize}

\section{Nouveautés de la 1.8.0}\label{sec:whats-new-1.8.0}

La version 1.8.0 est la septième version mineure thématique, «~Les
couvertures, franchement~». Elle rend le téléversement manuel de
couverture découvrable pour les titres qu'aucun fournisseur gratuit ne
couvrira jamais, et achève le refactor interne \texttt{base\_context()}
entamé en 1.7.11. \emph{Aucune migration de schéma, aucun changement de
réglage}~; mise à jour de routine \texttt{docker compose pull \&\& docker
compose up -d}.

\begin{itemize}
  \item \textbf{\#350 \string— l'option de téléversement manuel est
        désormais visible.} La page de détail d'un titre affiche un bouton
        «~Téléverser une couverture~» bien visible et une phrase
        d'explication quand le titre n'a pas de couverture~: beaucoup
        d'éditeurs français, suisses et allemands (Dunod, Eyrolles,
        Slatkine, Mardaga, Kana, Casterman) ne sont indexés ni par Google
        Books ni par Open Library, le téléversement manuel est donc la
        voie réaliste. Une couverture téléversée manuellement est protégée
        contre tout écrasement par une récupération automatique

        \texttt{POST /login/} ou \texttt{POST //login} (variantes
        que le routeur Axum dispatche identiquement vers
        \texttt{POST /login}) passaient par la validation CSRF au
        lieu d'être contournées. Nouvelle fonction
        \texttt{normalize\_exempt\_path} qui retire le slash final
        et fusionne les slashes répétés \string— les formes
        percent-encodées ne sont volontairement \emph{pas} décodées
        (la tentative de bypass \texttt{/login\%2F..\%2Fadmin} reste
        rejetée).
  \item \textbf{\#36 \string— bypass du résolveur de session sur
        les routes statiques.} \texttt{session\_resolve\_middleware}
        traversait le résolveur sur \emph{chaque} requête, y compris
        \texttt{/static/*}, \texttt{/covers/*} et \texttt{/logo/*}.
        Un seul chargement de la page d'accueil déclenchait des
        dizaines de requêtes d'assets, chacune lisant une ligne
        \texttt{sessions} (et insérant une ligne anonyme sur un
        onglet vierge). Le middleware court-circuite désormais ces
        préfixes en plus du bypass \texttt{/health} existant.
\end{itemize}

La version 1.7.5 est un patch ciblé qui groupe un correctif visible
utilisateur et sept commits de durcissement issus de
code-review-findings. \emph{Aucune migration de schéma, aucune

\section{Rollback}

Le rollback \emph{n'est pas} un flux de première classe. Les
migrations de schéma avancent uniquement — il n'y a pas de
\texttt{down.sql}. La stratégie de récupération supportée est :

\begin{enumerate}
  \item Restaurer la sauvegarde de base pré-mise-à-jour
        (chapitre~\ref{ch:backup}).
  \item Réépingler le tag d'image à la version antérieure.
  \item Démarrer la pile.
\end{enumerate}

Cela fonctionne car la sauvegarde est cohérente avec le schéma
antérieur. Tenter de pointer une image plus ancienne sur une base
fraîchement migrée échoue au boot.
