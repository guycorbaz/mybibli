\chapter{Mise à jour et migration}
\label{ch:upgrade}

Les mises à jour de routine sont conçues pour être sûres.
L'exception est le saut 1.0.x → 1.1.0, un breaking change unique
documenté ci-dessous.

\section{Mises à jour de routine (1.y → 1.z)}

\begin{enumerate}
  \item Lisez les notes de version pour chaque version entre votre
        version courante et la cible.
  \item Prenez une \textbf{sauvegarde de base} fraîche
        (chapitre~\ref{ch:backup}).
  \item Mettez à jour le tag d'image dans
        \texttt{docker-compose.yml} (ou re-tirez \texttt{:latest}
        si vous suivez ce tag).
  \item Lancez \texttt{docker compose up -d}. Le nouveau conteneur
        boote, exécute les nouvelles migrations contre la base
        existante, et reprend le service.
  \item Surveillez les logs pour les erreurs de migration :
        \texttt{docker compose logs mybibli | grep -i migrate}.
\end{enumerate}

Les migrations sont append-only — les changements de schéma sont
forward-compatibles. Une installation 1.4 mise à jour en 1.5 garde
toutes les lignes de 1.4 et applique les nouvelles tables /
colonnes sur place.

\begin{tip}
Pour les installations homelab, le tag Docker \texttt{:latest} est
un défaut raisonnable. Pour des montages production
(bibliothèque communautaire, association), épinglez une version
explicite pour qu'un \texttt{pull} non surveillé n'amène pas une
release sur laquelle vous n'avez pas lu les notes.
\end{tip}

\section{Le saut 1.0.x → 1.1.0}\label{sec:upgrade-1.1.0}

\begin{warning}
\textbf{Ceci est un breaking change unique.}\index{mise à jour 1.1.0}
Les installations 1.0.x sont sujettes au bug documenté dans
\href{https://github.com/guycorbaz/mybibli/issues/173}{\#173} :
les migrations seed créent les identifiants \texttt{admin/admin}
et \texttt{librarian/librarian} à chaque installation neuve, y
compris en production, et contournent silencieusement l'assistant
de première mise en service.
\end{warning}

Le chemin recommandé dépend de si votre installation 1.0.x détient
des données réelles :

\subsection*{Si votre installation 1.0.x est vide (aucun titre catalogué)}

Le chemin le plus simple : effacer la base et réinstaller en 1.1.0+.

\begin{enumerate}
  \item Arrêter la pile : \texttt{docker compose down}.
  \item Supprimer le volume de base :
        \texttt{docker volume rm mybibli\_mybibli\_db\_data}
        (ou l'équivalent sur votre hôte —
        \texttt{docker volume ls} les liste).
  \item Tirer l'image 1.1.0 : \texttt{docker compose pull}.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} si vous aviez épinglé une
        version antérieure.
  \item Démarrer : \texttt{docker compose up -d}.
  \item Ouvrir \texttt{/setup} et parcourir l'assistant.
\end{enumerate}

\subsection*{Si votre installation 1.0.x détient des données réelles}

\begin{enumerate}
  \item Prenez une sauvegarde de base (chapitre~\ref{ch:backup}).
  \item Prenez une sauvegarde covers + \texttt{.env}.
  \item Connectez-vous comme l'admin seedé et changez le mot de
        passe \emph{avant} la mise à jour. La mise à jour 1.1.0
        elle-même est sûre, mais la rotation ferme la dernière
        fenêtre pendant laquelle les identifiants par défaut
        pourraient fuiter.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} et lancer
        \texttt{docker compose up -d}.
  \item Le boot 1.1.0 détecte l'admin existant et n'active
        \emph{pas} l'assistant — l'admin avec mot de passe tourné
        reste l'admin actif.
\end{enumerate}

\subsection*{La nouvelle variable \texttt{MYBIBLI\_SEED\_DEV\_USERS}}

À partir de 1.1.0, la migration seed est gardée par
\texttt{MYBIBLI\_SEED\_DEV\_USERS}\index{MYBIBLI\_SEED\_DEV\_USERS}.
Le défaut est \texttt{0} (pas de seed). Ne la positionnez à
\texttt{1} que pour des flux de dev local ou des tests automatisés
— jamais en production. L'assistant de première mise en service
devient le chemin canonique d'onboarding.

\section{Lire les notes de version}

Chaque release mybibli publie une page GitHub Release avec :

\begin{itemize}
  \item un paragraphe résumant le changement ;
  \item l'impact migration (aucun / additif / breaking) ;
  \item un lien vers le diff contre le tag précédent ;
  \item les PDF de ce manuel (anglais + français) en pièce jointe
        une fois le build PDF de release câblé dans la CI.
\end{itemize}

Lisez les notes avant de mettre à jour. Les breaking changes
portent une étiquette \emph{Breaking} bien visible.

\section{Nouveautés de la 1.3.0}\label{sec:whats-new-1.3.0}

La version 1.3.0 est la deuxième version mineure thématique de
l'ère post-v1 \string— \textbf{Plan your next purchase}. Une
migration additive (\texttt{wishlist\_items}), aucun breaking
change \string— routine \texttt{docker compose pull \&\& docker
compose up -d}.

\begin{itemize}
  \item \textbf{Tableau par volume sur la page détail d'un titre
        (\#209).} Ouvrez n'importe quel titre et faites défiler
        après le bloc contributeurs~: une liste inline de tous
        les volumes actifs pour ce titre s'affiche, avec le
        code V (cliquable, lien vers \texttt{/volume/:id}), le
        nom de l'emplacement résolu et son code L, l'état, et
        \string— pour les Bibliothécaires et les Admins \string—
        les actions Modifier + Supprimer. Le bouton Supprimer
        ouvre une modale de confirmation UX-DR8~; sur succès,
        redirection vers la page détail du titre avec la liste
        des volumes re-rendue sans la ligne supprimée. Sur
        mobile, le tableau se transforme en pile de cartes selon
        le pattern dual-surface établi. Clôt l'issue GitHub
        \#209.
  \item \textbf{Wish list comme surface de premier ordre
        (\#242).} Une nouvelle surface \texttt{/wishlist},
        accessible depuis la barre de navigation (Bibliothécaire+
        pour les mutations, lecture accessible à tous). Deux
        modes d'ajout~: scanner ou saisir un ISBN à 13 chiffres
        pour que mybibli récupère les métadonnées via la chaîne
        de fournisseurs existante (carte de prévisualisation
        avec couverture, puis Confirmer) \string— ou choisir
        \emph{Saisie libre} et taper juste un titre (tout le
        reste optionnel). Chaque entrée peut être marquée
        \emph{Acheté} depuis la liste, la page détail, OU
        automatiquement quand le même ISBN est ensuite catalogué
        via \texttt{/catalog} \string— mybibli affiche un
        bandeau émeraude dans le feedback du scan proposant
        \emph{Retirer de la wish list} en un clic (aucune
        suppression silencieuse). La page \texttt{/wishlist/print}
        rend une mise en page d'impression épurée~; utilisez
        \emph{Imprimer en PDF} du navigateur pour emporter la
        liste à la librairie. Un nouveau compteur sur le tableau
        de bord affiche le nombre d'entrées (caché quand vide).
        Trace d'audit complète sur ajout et marquage comme
        acheté. Voir \autoref{sec:wishlist} pour la marche à
        suivre. Clôt l'issue GitHub \#242.
\end{itemize}

La ligne de patches 1.2.x reste en maintenance pour les bugs de
production qui ne justifient pas un bump de fonctionnalité.

\section{Nouveautés de la 1.2.2}\label{sec:whats-new-1.2.2}

La version 1.2.2 est un correctif de trois bugs en
\emph{defense-in-depth} sur 1.2.1, autour de la sémantique des
genres soft-deleted. Aucune migration de schéma, aucun breaking
change \string— routine
\texttt{docker compose pull \&\& docker compose up -d}.

Le garde de suppression de la story 8-4 empêche l'état orphan-FK
par la voie supportée~: on ne peut pas soft-deleter un genre qui
a encore des titres assignés. Ces fixes durcissent le contrat
côté lecture pour qu'une migration future, un
\texttt{UPDATE} SQL manuel ou un retrait du garde n'induise pas
silencieusement le bibliothécaire en erreur.

\begin{itemize}
  \item \textbf{Les liens de filtre genre périmés ne renvoient
        plus de listes vides silencieuses.} Ouvrez la home dans
        deux onglets, soft-deletez un genre depuis l'onglet
        admin reference-data, puis cliquez sur la puce filtre
        de ce genre dans l'autre onglet. Avant~: le SQL
        catalogue filtrait sur l'id du genre maintenant
        soft-deleted, la LISTE renvoyait vide, sans explication.
        Maintenant~: le handler home valide le genre cible du
        filtre, retire silencieusement la puce s'il pointe sur
        un genre supprimé, et affiche un bandeau d'information
        localisé (\emph{Ce genre n'existe plus \string—
        affichage de tous les titres.}) au-dessus des résultats
        pour expliquer ce qui s'est passé. Clôt l'issue GitHub
        \#112.
  \item \textbf{Les titres orphelins ne disparaissent plus du
        catalogue.} Les quatre requêtes SQL du catalogue
        (résultats de recherche, ajouts récents, catalogués
        récemment) utilisent désormais une jointure externe à
        gauche sur la table des genres, avec un
        \texttt{COALESCE} sur le nom du genre. Un titre dont le
        genre a été soft-deleted (orphan FK) disparaissait
        silencieusement de toutes les listes du catalogue~; il
        apparaît maintenant avec un placeholder localisé
        (\emph{(Genre supprimé)} / \emph{(Deleted genre)}) pour
        que vous puissiez le retrouver, lui réassigner un vrai
        genre et passer à autre chose. Clôt l'issue GitHub
        \#107.
  \item \textbf{Les pourcentages des statistiques par genre
        reflètent désormais la vraie part du catalogue.} Le
        panneau des pourcentages par genre sur la home
        calculait son dénominateur à partir de la somme des
        lignes affichées. Avec des titres orphan-FK actifs,
        cela gonflait le pourcentage de chaque ligne affichée
        (12 Roman + 8 BD + 5 orphan-Z affichait Roman à 60\%
        au lieu des 48\% véridiques). Le dénominateur provient
        désormais du compte total des titres actifs émis par
        la carte glance. En présence de titres orphan-FK, le
        total affiché est \(<\)100\%~; l'écart est le delta
        des orphelins et signale que certains titres pointent
        sur un genre soft-deleted. Clôt l'issue GitHub \#111.
\end{itemize}

\section{Nouveautés de la 1.2.1}\label{sec:whats-new-1.2.1}

La version 1.2.1 est un correctif de quatre bugs sur la 1.2.0.
Aucune migration de schéma, aucun breaking change \string— routine
\texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Supprimer une série avec des titres assignés
        affiche désormais le bon message d'erreur.} Tenter de
        supprimer une série qui possède encore des titres
        renvoyait le bandeau générique \emph{Une erreur interne
        est survenue}~; la vraie cause (\emph{Impossible de
        supprimer X~: N titre(s) assigné(s). Retirez d'abord
        toutes les assignations.}) ne sortait que dans les logs
        serveur. Le handler reconnaît maintenant aussi la
        variante \texttt{Conflict} retournée par le garde
        d'assignation, donc l'utilisateur voit le message
        actionnable et sait qu'il faut désassigner les titres
        d'abord. Clôt l'issue GitHub \#139.
  \item \textbf{Le bouton d'aide n'est plus imbriqué dans son
        \texttt{<label>}.} Six formulaires (étape admin de
        l'assistant, étape préférences de l'assistant, création
        et édition d'emprunteur pour les champs email \&
        téléphone, type de série, état de volume) rendaient le
        \texttt{<button>} d'aide à l'intérieur du
        \texttt{<label>} du contrôle de formulaire. HTML5
        interdit du contenu interactif dans \texttt{<label>}~;
        certains lecteurs d'écran propageaient aussi les clics
        sur le label vers le bouton d'aide, provoquant des
        sauts de focus parasites. Le bouton est désormais un
        frère du label dans un petit conteneur flex, et le
        tooltip s'affiche sous le déclencheur pour ne jamais
        recouvrir le contrôle de formulaire. Clôt l'issue
        GitHub \#154.
  \item \textbf{Le modal de retour de prêt revient maintenant à
        la page d'origine après connexion.} Un utilisateur
        anonyme arrivant sur la page \texttt{/borrower/:id} et
        cliquant sur \emph{Retour} pour un prêt actif était
        envoyé vers \texttt{/login} puis déposé sur la liste
        générique \texttt{/loans}, perdant le contexte
        emprunteur. Le handler lit désormais l'en-tête
        \texttt{HX-Current-URL} envoyé par HTMX, valide le
        chemin via le garde same-origin existant et l'utilise
        comme cible de retour post-connexion. Clôt l'issue
        GitHub \#133.
  \item \textbf{Le corps de la réponse 403 Interdit s'affiche
        désormais dans la langue de l'utilisateur.} Un
        utilisateur en locale française cliquant sur une action
        réservée à l'admin en étant Bibliothécaire (ou tout
        autre flux produisant un 403) voyait le texte d'erreur
        en anglais au lieu de la traduction française. La
        locale traverse maintenant le helper de vérification de
        permission jusqu'à la réponse d'erreur, donc tout corps
        Interdit est rendu dans la langue que l'utilisateur
        voit déjà partout ailleurs. Clôt l'issue GitHub \#219.
\end{itemize}

\section{Nouveautés de la 1.2.0}\label{sec:whats-new-1.2.0}

La version 1.2.0 est la première version mineure de l'ère post-v1
\string— six change-requests regroupées autour d'un même thème~:
\textbf{voir ce qu'on possède, le retrouver plus vite}. Aucune
migration de schéma au-delà d'une petite colonne additive utilisée
par la maintenance admin, aucun breaking change \string—~routine
\texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Le code Dewey juste à côté du genre.} La page
        détail d'un titre affiche désormais le code Dewey
        comme une puce dans la ligne type-de-média / genre /
        nombre-de-volumes en haut de page (quand il est défini).
        L'ancien paragraphe Dewey isolé plus bas a été retiré.
        Clôt l'issue GitHub \#236.
  \item \textbf{Tri d'une série par Dewey ou par titre.} La page
        détail d'une série gagne une rangée de liens de tri
        au-dessus de la grille de gaps. Trois clés~: \emph{position}
        (comportement d'origine, gardé en défaut), \emph{code
        Dewey} (titres assignés avec un Dewey d'abord, puis sans
        Dewey, puis les gaps \string— les gaps ne passent jamais
        devant, même en ordre décroissant), et \emph{titre}
        (alphabétique, insensible à la casse). La page détail
        d'un emplacement avait déjà la même colonne de tri Dewey
        depuis Epic 5~; la 1.2.0 achève la symétrie. Clôt
        l'issue GitHub \#235.
  \item \textbf{Plier / déplier l'arbre des Emplacements.}
        Chaque n\oe ud parent dans l'arbre \texttt{/locations}
        porte désormais un petit basculement \emph{▼ / ▶} devant
        sa ligne. Un clic masque la sous-arborescence~; l'état
        plié est conservé dans le localStorage du navigateur,
        donc la mise en page survit à un rechargement. Utile
        dès que la hiérarchie dépasse l'écran. Clôt l'issue
        GitHub \#200.
  \item \textbf{Filtre «~Sans genre~» en un clic.} La page
        d'accueil gagne une puce de filtre dédiée à côté des
        puces par genre. Un clic affiche les titres dont le
        genre est la valeur par défaut \texttt{Non classé}~:
        ceux que la chaîne de récupération de métadonnées n'a
        pas pu classer et que vous n'avez pas reclassés. Clôt
        l'issue GitHub \#205.
  \item \textbf{Indicateur de chargement sur «~Appliquer les
        modifications choisies~».} Le formulaire de
        confirmation des conflits de métadonnées \string—~celui
        qui apparaît au re-fetch d'un titre avec des champs
        édités à la main \string—~affiche désormais un spinner
        dans le bouton \emph{Appliquer} pendant que la requête
        est en vol. Plus de doute sur le fait que le clic a
        bien été pris en compte. Clôt l'issue GitHub \#215.
  \item \textbf{Récupération en lot des couvertures manquantes.}
        Le panneau \texttt{/admin?tab=health} gagne une section
        \emph{Maintenance} avec un compteur des titres sans
        couverture et un bouton \emph{Récupérer les couvertures
        manquantes}. Un clic lance une tâche d'arrière-plan qui
        parcourt les titres éligibles (ceux avec au moins un
        code ISBN / ISSN / UPC, ordonnés du plus ancien au plus
        récent) et re-déclenche la chaîne complète de récupération
        de métadonnées sur chacun \string—~y compris le repli
        Open Library Covers introduit en v1.1.6/1.1.7. Un délai
        de 500\,ms entre titres garde les fournisseurs heureux~;
        un verrou unique refuse les clics concurrents avec un
        message amical. Clôt l'issue GitHub \#214.
\end{itemize}

\section{Nouveautés de la 1.1.9}\label{sec:whats-new-1.1.9}

La version 1.1.9 est une release mono-correctif au-dessus de la
1.1.8. Aucune migration de schéma, aucun breaking change
\string— routine \texttt{docker compose pull \&\& docker compose
up -d}.

\begin{itemize}
  \item \textbf{Sauvegarder un titre n'échoue plus silencieusement
        quand des champs numériques sont vides.} Le formulaire
        d'édition comporte quatre champs numériques (nombre de
        pages, pistes, durée, numéro). Pour un titre où le champ
        est \texttt{NULL} (cas fréquent sur les livres français
        dont la BnF n'a pas fourni le nombre de pages), l'input
        s'affiche vide. Cliquer \emph{Sauver} renvoyait HTTP~422
        \emph{Unprocessable Entity} \string— le navigateur
        envoyait \texttt{page\_count=} (chaîne vide) et le
        désérialiseur du formulaire le refusait comme non-numéro.
        Symptôme particulièrement pénible~: la page restait
        affichée, sans retour, sans changement persisté, seule
        la console du navigateur mentionnait le 422. La 1.1.9
        fait passer les quatre champs numériques
        \texttt{Option} par le désérialiseur tolérant aux
        chaînes vides déjà en place pour le formulaire de
        série, donc une entrée vide est correctement comprise
        comme \emph{non fournie} et la sauvegarde aboutit.
        Clôt l'issue GitHub \#238.
\end{itemize}

\section{Nouveautés de la 1.1.8}\label{sec:whats-new-1.1.8}

La version 1.1.8 clôt le troisième bug de la saga
\emph{cover-fallback} (\#225 → \#228 → \#232) et apporte les
premières illustrations du manuel. Une petite migration de schéma
accompagne cette release \string— révisez la section sur les
mises à jour de routine si vous n'avez pas vu de release avec
migration depuis un moment, mais le changement est purement
données (pas de diff de schéma cassant).

\begin{itemize}
  \item \textbf{Le Re-fetch télécharge enfin la couverture des
        titres dont seul le genre avait été personnalisé.} Les
        releases précédentes branchaient le repli Open Library
        Covers à la fois sur le chemin de scan en arrière-plan
        (1.1.6) et sur le chemin Re-fetch metadata déclenché par
        l'utilisateur (1.1.7), mais le formulaire renvoyé par
        Re-fetch cachait toujours la couverture derrière une case
        à cocher \emph{accept cover} non cochée dès que
        \texttt{manually\_edited\_fields} n'était pas vide.
        L'enquête a montré que mybibli enregistrait chaque
        changement de \emph{genre} dans cette liste, alors
        qu'aucun fournisseur de métadonnées ne renvoie le genre.
        Conséquence~: chaque titre que vous aviez déjà reclassé
        était bloqué de façon permanente sur le flux de
        confirmation des conflits, et un Re-fetch en un clic
        laissait silencieusement tomber la couverture. La 1.1.8
        arrête de suivre \texttt{genre\_id} dans
        \texttt{manually\_edited\_fields}, embarque une migration
        de données mono-coup qui retire l'entrée parasite des
        lignes existantes, et passe à \texttt{NULL} les tableaux
        qui deviennent vides, de sorte que le prochain Re-fetch
        sur ces titres prend la branche \emph{direct-apply}
        \string— métadonnées rafraîchies et couverture
        téléchargée en silence quand Open Library en a une.
        Clôt l'issue GitHub \#232.
  \item \textbf{Illustrations.} Le chapitre~\ref{ch:usage}
        (\emph{Usage au quotidien}) et le
        chapitre~\ref{ch:bestpractices} (\emph{Bonnes pratiques})
        portent désormais des captures d'écran annotées prises
        sur une installation de production réelle \string— un
        tableau de bord d'accueil avec le champ de scan, les
        puces de genres, les compteurs et les ajouts récents, et
        un arbre Emplacements avec la hiérarchie pièce~/
        bibliothèque~/ étagère du foyer. Les mêmes images
        ouvrent maintenant le README du projet et la page
        d'accueil du site web.
\end{itemize}

\section{Nouveautés de la 1.1.7}\label{sec:whats-new-1.1.7}

La version 1.1.7 est un suivi mono-correctif de la 1.1.6 \string—
même surface (le repli Open Library Covers introduit pour
l'issue \#225), code path différent. Aucune migration de schéma,
aucun breaking change \string— routine \texttt{docker compose
pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Re-fetch metadata applique enfin le repli
        couverture.} La 1.1.6 avait branché le repli Open Library
        Covers dans le code path \emph{background} de
        récupération de métadonnées (déclenché au scan d'un
        nouvel ISBN) mais avait raté le bouton \emph{Re-fetch
        metadata} de la page détail d'un titre. Bug symétrique~:
        les titres FR résolus par la BnF restaient sans
        couverture sur re-fetch alors qu'Open Library en avait
        peut-être une indexée par ISBN. La 1.1.7 extrait un
        helper unique
        (\texttt{CoverService::resolve\_cover\_url\_with\_fallback})
        utilisé par tous les chemins qui téléchargent une
        couverture pour un résultat de métadonnées résolu
        \string— scan background, application directe sur
        re-fetch (sans édition manuelle), et la case
        \emph{accept cover} du formulaire de confirmation
        de conflits. Pour récupérer un titre laissé sans
        couverture, ré-ouvrir sa page détail et cliquer
        \emph{Re-fetch metadata}~; la couverture arrive
        désormais dans la même requête quand Open Library
        la possède. Clôt l'issue GitHub \#228.
\end{itemize}

\section{Nouveautés de la 1.1.6}\label{sec:whats-new-1.1.6}

La version 1.1.6 est une release mono-correctif au-dessus de la
1.1.5. Aucune migration de schéma, aucun breaking change
\string— routine \texttt{docker compose pull \&\& docker compose
up -d}.

\begin{itemize}
  \item \textbf{Couvertures pour les titres résolus par la BnF.}
        La chaîne de fournisseurs de métadonnées fonctionne en
        «~premier qui répond gagne tout~». Quand la BnF (le
        premier fournisseur livres pour le français) résolvait un
        titre, elle remplissait les champs textuels mais jamais
        l'URL de couverture \string— l'UNIMARC XML que la BnF
        renvoie via son API SRU ne contient tout simplement pas
        d'URL d'image. Même symptôme pour les résultats Google
        Books sans bloc \texttt{imageLinks} (cas fréquent pour les
        titres auto-édités sur Amazon KDP). La chaîne ne se
        rabattait pas sur Open Library pour la seule couverture,
        donc la majorité des fiches du catalogue restaient sans
        jaquette même quand Open Library en avait une.

        mybibli effectue désormais un repli ciblé couverture~:
        quand la chaîne renvoie des métadonnées sans
        \texttt{cover\_url} et que le code interrogé est un ISBN,
        mybibli interroge l'\emph{API Open Library Covers}
        (\url{https://covers.openlibrary.org/b/isbn/}) en
        \texttt{HEAD}. Sur \texttt{200}, la couverture est
        téléchargée, redimensionnée à 400~px de large et stockée
        en JPEG 80~\%, exactement comme si le fournisseur initial
        l'avait fournie. Sur \texttt{404} / erreur réseau / code
        non ISBN, le titre reste sans couverture mais
        silencieusement (pas de bruit de log par couverture
        manquante).

        Pour récupérer les couvertures sur les titres déjà
        catalogués avant cette release, ouvrir la fiche détail du
        titre concerné et cliquer \emph{Re-fetch metadata}. Une
        action admin de re-fetch en masse est suivie à l'issue
        \#214. Clôt l'issue GitHub \#225.
\end{itemize}

\section{Nouveautés de la 1.1.5}\label{sec:whats-new-1.1.5}

La version 1.1.5 poursuit la série de patchs issus de retours
utilisateur, par-dessus la 1.1.4. Aucune migration de schéma, aucun
breaking change \string— routine \texttt{docker compose pull \&\&
docker compose up -d}. Trois améliorations~:

\begin{itemize}
  \item \textbf{Sauvegarde d'un titre sans métadonnées.} Quand la
        chaîne de fournisseurs ne renvoie rien pour un ISBN scanné
        (BnF / Google Books / Open Library tous muets), le titre
        était créé avec le genre \texttt{Non classé} par défaut,
        mais une sauvegarde manuelle depuis le formulaire d'édition
        pouvait déclencher une violation de FK si le
        \texttt{genre\_id} soumis valait 0 \string— cas limite qui
        touchait les utilisateurs qui éditaient un titre fraîchement
        scanné dont le dropdown n'avait aucune pré-sélection. Le
        handler bascule désormais sur \texttt{Non classé} pour tout
        \texttt{genre\_id == 0}, et la résolution sous-jacente
        s'auto-répare (réactive une ligne soft-deleted, ré-amorce
        si elle est absente). Clôt l'issue GitHub \#203.
  \item \textbf{Durcissement de l'en-tête Modal-Confirm.} Le
        \texttt{ModalConfirmRetargetGuard} exige maintenant
        \texttt{X-Modal-Confirm: true} ET \texttt{HX-Request: true}
        avant de retirer \texttt{HX-Retarget} / \texttt{HX-Reswap}
        d'une réponse. Un client non HTMX (curl, wget, script non
        navigateur) ne peut plus déclencher ce strip simplement en
        envoyant l'en-tête modal. Défense en profondeur \string—
        le modèle de menace garde ce point en sévérité basse pour
        le déploiement single-tenant LAN. Clôt l'issue GitHub
        \#218.
  \item \textbf{Guide de configuration Google Books.} Le chapitre
        sur les fournisseurs de métadonnées
        (Chapitre~\ref{ch:providers}) comporte désormais une
        procédure pas-à-pas pour la Google Cloud Console (clé de la
        Books API), ainsi qu'une section \emph{Dépannage~:
        métadonnées vides} pour les cas où un scan repart avec des
        champs vides. Tranche docs de l'issue GitHub \#202~; les
        idées plus larges sur la visibilité par fournisseur (badge
        source des métadonnées, retry par fournisseur, surfaçage
        structuré des erreurs) restent ouvertes pour des stories
        futures.
\end{itemize}

\section{Nouveautés de la 1.1.4}\label{sec:whats-new-1.1.4}

La version 1.1.4 est une release à un seul correctif. Pas de
migration de schéma ni de breaking change côté \emph{application}
\string— mais la mise à jour requiert une modification de
\texttt{docker-compose.yml}, raison pour laquelle l'histoire de la
persistance des couvertures est documentée principalement dans le
chapitre Installation plutôt qu'ici.

\begin{itemize}
  \item \textbf{Persistance des couvertures à travers les mises à
        jour de conteneur.} Le \texttt{docker-compose.yml} publié
        déclare désormais un volume nommé \texttt{mybibli\_covers}
        monté sur \texttt{/app/covers}, en parallèle de
        \texttt{mybibli\_db\_data}. Avant la 1.1.4 les JPG des
        couvertures vivaient dans la couche d'écriture du conteneur
        et étaient détruits à chaque \texttt{docker compose up -d}
        suivant un \texttt{pull}. Les utilisateurs déjà installés
        en pré-1.1.4 doivent re-télécharger les couvertures depuis
        la page de détail de chaque titre concerné \string— une
        action admin de bulk-fetch est suivie à l'issue GitHub
        \#214. Clôt l'issue GitHub \#213.
\end{itemize}

\section{Nouveautés de la 1.1.3}\label{sec:whats-new-1.1.3}

La version 1.1.3 est le premier patch issu de retours utilisateur de
production, par-dessus la 1.1.2. Aucune migration de schéma, aucun
breaking change \string— routine \texttt{docker compose pull \&\&
docker compose up -d}. Deux améliorations visibles côté utilisateur~:

\begin{itemize}
  \item \textbf{Réorganisation de la page d'accueil.} La zone des
        résultats filtrés/recherchés (la liste qui se met à jour
        quand vous cliquez sur une étiquette de genre ou tapez dans
        le champ de recherche) se trouve maintenant directement sous
        le champ de recherche, AU-DESSUS des indicateurs (ajouts
        récents, retours récents, statistiques par genre, etc.).
        Avant la 1.1.3 les résultats apparaissaient tout en bas de
        la page \string— cliquer sur une étiquette déclenchait bien
        le swap, mais celui-ci se faisait cinq écrans plus bas, hors
        de votre viewport, donc on avait l'impression que rien ne se
        passait. Clôt l'issue GitHub \#204.
  \item \textbf{Lignes de l'arborescence Emplacements cliquables.}
        Sur la page \texttt{/locations}, cliquer sur le nom d'un
        emplacement (ou son icône, son L-code, son type, son
        compteur de volumes) navigue vers \texttt{/location/:id}~:
        la liste des volumes de cet emplacement, avec colonnes
        triables (titre, auteur, genre, Dewey). Les boutons
        d'édition/suppression/ajout-enfant restent cliquables
        individuellement EN DEHORS du lien. Clôt l'issue GitHub
        \#208.
\end{itemize}

\section{Nouveautés de la 1.1.2}\label{sec:whats-new-1.1.2}

La version 1.1.2 clôt l'Epic~10 — polish UX mobile et closeout
sécurité. Aucune migration de schéma, aucun breaking change.
La mise à jour est un simple \texttt{docker compose pull \&\&
docker compose up -d} de routine. Les améliorations visibles
côté utilisateur :

\begin{itemize}
  \item \textbf{Les tableaux deviennent des cartes sur mobile.}
        Catalogue, prêts, emprunteurs et séries s'affichent sous
        forme de cartes compactes sur les viewports étroits
        (en-dessous du breakpoint Tailwind \texttt{md}). La mise
        en page tableau desktop reste inchangée. Les deux formats
        rendent les mêmes lignes — le basculement est purement CSS,
        sans JavaScript.
  \item \textbf{Les onglets admin deviennent une liste déroulante
        sur mobile.} Sur les écrans étroits, les cinq onglets de
        l'admin (Santé, Utilisateurs, Données de référence, Corbeille,
        Système) se replient en \texttt{<select>} au lieu de
        déborder horizontalement. Les liens profonds
        \texttt{/admin?tab=...} continuent de fonctionner.
  \item \textbf{Le message «~Session expirée~» est désormais
        explicite.} Quand le jeton CSRF de session dérive (par
        exemple parce que le navigateur est resté inactif au-delà
        du timeout et que la session a tourné), l'action suivante
        affiche maintenant une bannière serveur claire au lieu
        d'échouer silencieusement. Le même flux gère les 403 de
        timeout de session.
  \item \textbf{Couverture accessibilité étendue aux pages
        d'entité.} Le gate WCAG~2.2~AA en CI couvre désormais
        chaque \texttt{/title/:id}, \texttt{/borrower/:id},
        \texttt{/contributor/:id}, \texttt{/series/:id} et
        l'assistant de première installation \texttt{/setup}, pas
        seulement les routes de navigation principales. Deux
        violations de contraste sur la page détail titre et sur le
        bloc «~ajouts récents~» de la page d'accueil ont été
        corrigées au passage.
  \item \textbf{Posture d'authentification documentée bout en bout.}
        \texttt{docs/auth-threat-model.md} formalise désormais la
        forme de déploiement single-tenant LAN/NAS : ce que CSRF
        protège, ce que font les cookies de session, le pourquoi
        des choix de conception et ce qu'il faudrait revisiter si
        le multi-tenant devenait un objectif. Référencé depuis
        \texttt{README.md} et \texttt{CLAUDE.md}.
\end{itemize}

\section{Rollback}

Le rollback \emph{n'est pas} un flux de première classe. Les
migrations de schéma avancent uniquement — il n'y a pas de
\texttt{down.sql}. La stratégie de récupération supportée est :

\begin{enumerate}
  \item Restaurer la sauvegarde de base pré-mise-à-jour
        (chapitre~\ref{ch:backup}).
  \item Réépingler le tag d'image à la version antérieure.
  \item Démarrer la pile.
\end{enumerate}

Cela fonctionne car la sauvegarde est cohérente avec le schéma
antérieur. Tenter de pointer une image plus ancienne sur une base
fraîchement migrée échoue au boot.
