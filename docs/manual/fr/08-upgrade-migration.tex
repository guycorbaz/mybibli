\chapter{Mise à jour et migration}
\label{ch:upgrade}

Les mises à jour de routine sont conçues pour être sûres.
L'exception est le saut 1.0.x → 1.1.0, un breaking change unique
documenté ci-dessous.

\section{Mises à jour de routine (1.y → 1.z)}

\begin{enumerate}
  \item Lisez les notes de version pour chaque version entre votre
        version courante et la cible.
  \item Prenez une \textbf{sauvegarde de base} fraîche
        (chapitre~\ref{ch:backup}).
  \item Mettez à jour le tag d'image dans
        \texttt{docker-compose.yml} (ou re-tirez \texttt{:latest}
        si vous suivez ce tag).
  \item Lancez \texttt{docker compose up -d}. Le nouveau conteneur
        boote, exécute les nouvelles migrations contre la base
        existante, et reprend le service.
  \item Surveillez les logs pour les erreurs de migration :
        \texttt{docker compose logs mybibli | grep -i migrate}.
\end{enumerate}

Les migrations sont append-only — les changements de schéma sont
forward-compatibles. Une installation 1.4 mise à jour en 1.5 garde
toutes les lignes de 1.4 et applique les nouvelles tables /
colonnes sur place.

\begin{tip}
Pour les installations homelab, le tag Docker \texttt{:latest} est
un défaut raisonnable. Pour des montages production
(bibliothèque communautaire, association), épinglez une version
explicite pour qu'un \texttt{pull} non surveillé n'amène pas une
release sur laquelle vous n'avez pas lu les notes.
\end{tip}

\section{Le saut 1.0.x → 1.1.0}\label{sec:upgrade-1.1.0}

\begin{warning}
\textbf{Ceci est un breaking change unique.}\index{mise à jour 1.1.0}
Les installations 1.0.x sont sujettes au bug documenté dans
\href{https://github.com/guycorbaz/mybibli/issues/173}{\#173} :
les migrations seed créent les identifiants \texttt{admin/admin}
et \texttt{librarian/librarian} à chaque installation neuve, y
compris en production, et contournent silencieusement l'assistant
de première mise en service.
\end{warning}

Le chemin recommandé dépend de si votre installation 1.0.x détient
des données réelles :

\subsection*{Si votre installation 1.0.x est vide (aucun titre catalogué)}

Le chemin le plus simple : effacer la base et réinstaller en 1.1.0+.

\begin{enumerate}
  \item Arrêter la pile : \texttt{docker compose down}.
  \item Supprimer le volume de base :
        \texttt{docker volume rm mybibli\_mybibli\_db\_data}
        (ou l'équivalent sur votre hôte —
        \texttt{docker volume ls} les liste).
  \item Tirer l'image 1.1.0 : \texttt{docker compose pull}.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} si vous aviez épinglé une
        version antérieure.
  \item Démarrer : \texttt{docker compose up -d}.
  \item Ouvrir \texttt{/setup} et parcourir l'assistant.
\end{enumerate}

\subsection*{Si votre installation 1.0.x détient des données réelles}

\begin{enumerate}
  \item Prenez une sauvegarde de base (chapitre~\ref{ch:backup}).
  \item Prenez une sauvegarde covers + \texttt{.env}.
  \item Connectez-vous comme l'admin seedé et changez le mot de
        passe \emph{avant} la mise à jour. La mise à jour 1.1.0
        elle-même est sûre, mais la rotation ferme la dernière
        fenêtre pendant laquelle les identifiants par défaut
        pourraient fuiter.
  \item Mettre à jour le tag d'image dans
        \texttt{docker-compose.yml} et lancer
        \texttt{docker compose up -d}.
  \item Le boot 1.1.0 détecte l'admin existant et n'active
        \emph{pas} l'assistant — l'admin avec mot de passe tourné
        reste l'admin actif.
\end{enumerate}

\subsection*{La nouvelle variable \texttt{MYBIBLI\_SEED\_DEV\_USERS}}

À partir de 1.1.0, la migration seed est gardée par
\texttt{MYBIBLI\_SEED\_DEV\_USERS}\index{MYBIBLI\_SEED\_DEV\_USERS}.
Le défaut est \texttt{0} (pas de seed). Ne la positionnez à
\texttt{1} que pour des flux de dev local ou des tests automatisés
— jamais en production. L'assistant de première mise en service
devient le chemin canonique d'onboarding.

\section{Lire les notes de version}

Chaque release mybibli publie une page GitHub Release avec :

\begin{itemize}
  \item un paragraphe résumant le changement ;
  \item l'impact migration (aucun / additif / breaking) ;
  \item un lien vers le diff contre le tag précédent ;
  \item les PDF de ce manuel (anglais + français) en pièce jointe
        une fois le build PDF de release câblé dans la CI.
\end{itemize}

Lisez les notes avant de mettre à jour. Les breaking changes
portent une étiquette \emph{Breaking} bien visible.

\section{Nouveautés de la 1.5.2}\label{sec:whats-new-1.5.2}

La version 1.5.2 est un hotfix d'une seule correction sur la
v1.5.1 : le flux de valorisation v1.5.0 \#243 était partiellement
cassé en production. Enregistrer un \emph{prix d'achat} ou une
\emph{valeur actuelle estimée} sur un volume écrivait bien la
valeur (les totaux de \texttt{/stats/value} et l'indicateur de
l'accueil reflétaient le nouveau montant), mais retournait un
500 à l'utilisateur, et chaque consultation suivante du volume
plantait.

Cause racine : SQLx 0.8 ne sait pas décoder une colonne
MariaDB \texttt{DECIMAL(10,2)} brute en \texttt{Option<f64>}
sans la feature \texttt{bigdecimal} ou \texttt{rust\_decimal}.
Le côté écriture fonctionnait parce que le driver convertit
\texttt{f64 \string→ DECIMAL} ; le côté lecture non. Les
requêtes d'agrégation (totaux de \texttt{/stats/value})
utilisaient déjà \texttt{CAST(SUM(...) AS DOUBLE)} et n'étaient
pas affectées.

Correctif : \texttt{VolumeModel::find\_by\_id} et
\texttt{find\_by\_label} entourent désormais les deux colonnes
DECIMAL avec \texttt{CAST(... AS DOUBLE)}. Deux nouveaux tests
\texttt{sqlx::test} de garde-fou INSERT un volume avec des
colonnes de valorisation non nulles et vérifient le
round-trip, empêchant le bug de réapparaître silencieusement.

Pas de migration de schéma, pas de changement cassant
\string— mise à jour routinière \texttt{docker compose pull
\&\& docker compose up -d}.

\section{Nouveautés de la 1.5.1}\label{sec:whats-new-1.5.1}

La version 1.5.1 est un correctif de cinq bugs de production
livré dans les heures qui ont suivi la mise à niveau du NAS en
v1.5.0. Pas de migration de schéma, pas de changement cassant
\string— mise à jour routinière \texttt{docker compose pull
\&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Plantage du PDF de la wish list (\#281).} Le
        Dockerfile v1.5.0 n'a jamais reçu de \texttt{COPY
        static/fonts/} quand la CR \#266 a embarqué les TTF
        DejaVu Sans, donc \texttt{/wishlist/export.pdf}
        retournait 500 en production. Correctif : une ligne
        ajoutée au Dockerfile.
  \item \textbf{Suppression définitive d'un titre depuis la
        Corbeille plantait (\#282).} Les 4 FK enfants qui
        référencent \texttt{titles} (\texttt{volumes},
        \texttt{title\_contributors}, \texttt{title\_series},
        \texttt{pending\_metadata\_updates}) utilisent la
        contrainte RESTRICT par défaut ; MariaDB rejetait la
        suppression du parent dès qu'une ligne enfant y faisait
        référence \string— même supprimée en doux, parce que les
        FK ne considèrent pas \texttt{deleted\_at}. Correctif :
        \texttt{TrashService::permanent\_delete} ouvre maintenant
        une transaction et casse les enfants dans l'ordre FK
        avant de supprimer le parent.
  \item \textbf{Bascule de la valorisation absente de
        \texttt{/admin?tab=system} (\#283).} La CR v1.5.0 \#243
        avait ajouté \texttt{default\_currency} +
        \texttt{show\_value\_indicators} dans la table settings
        et le cache AppSettings, mais aucune interface n'avait
        été câblée pour les modifier. Correctif : une nouvelle
        section « Valorisation » sur l'onglet Système avec une
        liste déroulante de devise + la case à cocher
        d'indicateur opt-in.
  \item \textbf{Impossible de supprimer une clé d'API révoquée
        (\#284).} L'implémentation v1.4.0 \#241 conservait
        volontairement les lignes révoquées pour l'audit, mais
        la liste grossissait sans fin. Correctif : un bouton
        Supprimer sur les lignes révoquées (boîte modale UX-DR8)
        appelle un nouveau handler \texttt{DELETE /admin/api-keys/\{id\}}.
        Les clés actives ne montrent toujours que Révoquer. Les
        références d'audit aux clés supprimées survivent (le
        lien est logique, pas une FK de schéma).
  \item \textbf{Onglet d'administration Santé marquait tous les
        fournisseurs en rouge (\#285).} \texttt{probe\_once}
        envoyait HEAD sans User-Agent et traitait les réponses
        4xx comme « down » \string— la plupart des WAF des
        fournisseurs répondent 4xx aux HEAD anonymes même quand
        l'API fonctionne. Correctif : le probe envoie
        désormais \texttt{User-Agent: mybibli/1.x.y} comme le
        chemin réel de récupération des métadonnées et traite
        toute réponse HTTP comme Reachable (seuls les timeouts /
        DNS / connexions refusées comptent comme Unreachable).
\end{itemize}

\section{Nouveautés de la 1.5.0}\label{sec:whats-new-1.5.0}

La version 1.5.0 est la quatrième version mineure thématique de
l'ère post-v1 \string— \textbf{Sachez ce que vous avez, et ce que
ça vaut}. Une migration de schéma additive (5 colonnes nullable
sur la table \texttt{volumes} + deux nouveaux paramètres dans
\texttt{settings}), pas de changement cassant \string— mise à jour
routinière \texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Fournisseur de métadonnées Library of Congress
        (\#263).} Source bibliographique faisant autorité pour
        les titres en anglais, placée dans la chaîne entre Google
        Books et Open Library : \texttt{BnF \string→ Google Books
        \string→ Library of Congress \string→ Open Library}.
        Comble le manque sur les ouvrages anciens, académiques
        ou US gouvernementaux que Google Books ne couvre pas.
  \item \textbf{Donut chart pour stats-by-genre sur l'accueil
        (\#265).} Remplace les barres de progression par un
        donut Chart.js v4. Les genres \(\geq\) 5\% du catalogue
        actif ont leur propre tranche ; les plus petits sont
        regroupés dans « Autres » avec un \texttt{<details>}
        listant les genres regroupés. Clic sur une tranche ou
        sur une entrée de légende \string→
        \texttt{/?filter=genre:N}. Chart.js est embarqué dans
        \texttt{static/js/vendor/} \string— aucun CDN, CSP reste
        strict.
  \item \textbf{Supprimer un titre sans volume (\#271).} Nouveau
        bouton Supprimer sur \texttt{/title/:id} (Bibliothécaire+,
        visible uniquement quand le titre n'a aucun volume actif)
        qui ouvre une boîte modale UX-DR8. À la confirmation, le
        titre est marqué comme supprimé et l'utilisateur est
        redirigé sur l'accueil ; la ligne est récupérable depuis
        la Corbeille pendant 30 jours.
  \item \textbf{Modifier ISBN / ISSN / UPC dans le formulaire de
        métadonnées (\#272).} Les lignes d'identifiants
        précédemment en lecture seule sont maintenant des
        champs éditables. Le checksum ISBN-13 est validé côté
        serveur ; une collision avec l'ISBN d'un autre titre
        retourne 409 avec un retour utilisateur clair. Compagnon
        de \#271 \string— les deux résolvent le scénario du
        titre bloqué après un mauvais scan.
  \item \textbf{Vrai export PDF pour la wish list (\#266).}
        Remplace le HTML print-to-PDF du navigateur (v1.3.1)
        par un vrai PDF généré côté serveur via \texttt{genpdf}
        (Rust pur, pas de sous-processus). Le bouton Imprimer
        sur \texttt{/wishlist} télécharge maintenant directement
        \texttt{wishlist-YYYY-MM-DD.pdf} \string— texte
        sélectionnable, recherchable, rendu identique dans tous
        les navigateurs. DejaVu Sans embarquée pour le support
        unicode.
  \item \textbf{Valorisation de la collection (\#243).} Deux
        nouveaux champs optionnels par volume \string— \emph{Prix
        d'achat} et \emph{Valeur actuelle estimée} \string— avec
        une devise ISO 4217 par champ. Agrégations sur une
        nouvelle page \texttt{/stats/value} (Bibliothécaire+) :
        total par devise, valeur par genre, valeur par série.
        Les catalogues multi-devises affichent une ligne par
        devise (la conversion FX est reportée à une future CR).
        Indicateur opt-in sur l'accueil \string— désactivé par
        défaut, basculable depuis \texttt{/admin?tab=system}.
        La devise par défaut est seedée à \texttt{CHF} et
        admin-modifiable. Toutes les vues liées à la valeur sont
        owner-facing (Bibliothécaire+) ; un visiteur anonyme ne
        voit jamais d'argent.
\end{itemize}

\section{Nouveautés de la 1.4.0}\label{sec:whats-new-1.4.0}

La version 1.4.0 est la troisième version mineure thématique de
l'ère post-v1 \string— \textbf{Apportez votre propre agent}. Une
migration de schéma additive (table \texttt{api\_keys}), pas de
changement cassant \string— mise à jour routinière
\texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{API JSON HTTP sous \texttt{/api/v1/*} (\#241).} Une
        nouvelle API authentifiée expose le catalogue à des scripts
        externes et à des outils basés sur des LLM. Les points
        d'entrée en lecture couvrent les titres (liste, détail,
        par bucket Dewey), les genres, les emplacements et les
        séries. Un point d'entrée d'écriture restreint
        \texttt{PATCH /api/v1/titles/\{id\}} modifie quatre
        champs en liste blanche (sous-titre, description, code
        Dewey, genre) avec verrouillage optimiste et une ligne
        d'audit complète par modification. Voir le nouveau chapitre
        11 \emph{API \string& intégrations} pour les contrats des
        points d'entrée, l'authentification et trois exemples
        Python / curl / boucle LLM.
  \item \textbf{Onglet d'administration Clés d'API.} Nouvelle
        surface \texttt{/admin?tab=api\_keys} pour créer, lister
        et révoquer des clés. La valeur en clair de chaque
        nouvelle clé est affichée \emph{une seule fois} dans une
        boîte modale UX-DR8 \string— ensuite seuls le hachage
        argon2 et un préfixe de 12 caractères sont persistés.
        Deux portées : \emph{lecture seule} (points d'entrée
        GET) et \emph{lecture + écriture} (ajoute PATCH). La
        liste affiche le libellé, la portée, le préfixe,
        l'horodatage de création, l'horodatage de dernière
        utilisation et le statut (active / révoquée). La
        révocation est réversible au sens où l'on peut toujours
        recréer une clé avec le même libellé, mais une clé
        révoquée ne peut plus jamais s'authentifier.
  \item \textbf{Pas de CSRF sur \texttt{/api/*}.}
        L'authentification par jeton ne repose pas sur les
        cookies, donc le middleware CSRF court-circuite tout le
        préfixe \texttt{/api/*}. Les points d'entrée formulaires
        de l'interface humaine restent protégés CSRF.
  \item \textbf{Chapitre 11 du manuel \emph{API \string&
        intégrations} (FR + EN).} Détaille la création des clés,
        la forme de l'authentification, chaque point d'entrée
        et trois exemples de bout en bout \string— une fiche
        \texttt{curl}, une boucle de pagination Python et une
        boucle de classificateur LLM en pseudo-code.
\end{itemize}

La version 1.3.1 est un correctif de quatre papercuts UX
remontés par Guy dans les heures suivant le déploiement de la
1.3.0 en production. Aucune migration de schéma, aucun breaking

\begin{itemize}

        1.3.0 partait sans indicateur visuel, ce qui laissait
        l'utilisateur dans le doute. Le bouton affiche
        maintenant une roue pendant la requête, et est
        désactivé pour bloquer les doubles-clics.
  \item \textbf{Tooltip d'aide sur la case Omnibus (\#259).}
        L'option Omnibus dans le formulaire d'assignation à une
        série sur la page détail d'un titre était opaque
        \string— un utilisateur fraîchement déployé a dû
        demander à quoi elle servait. Un nouveau tooltip
        explique~: \emph{cochez si le livre regroupe plusieurs
        volumes de la série~; le formulaire révèle alors un
        champ Position de fin pour que le titre couvre une
        plage de positions au lieu d'une seule.}
  \item \textbf{Page d'impression de la wish list revue
        (\#260).} Le bouton Imprimer ouvre désormais
        \texttt{/wishlist/print} dans un \emph{nouvel onglet}
        pour ne pas perdre la vue wish list quand on ferme la
        boîte de dialogue d'impression. La page d'impression
        elle-même a été refondue d'un tableau dense en une mise
        en page en cartes avec vignettes de couverture, une
        hiérarchie typographique plus claire (titre en gras,
        auteur estompé), un pied de page avec le compteur de
        pages, et des règles CSS pour qu'une entrée ne soit
        jamais coupée entre deux pages. Le PDF est prêt à
        emporter en librairie.
  \item \textbf{Section "Ajouts récents" repliée par défaut sur
        la home (\#261).} À mesure que le catalogue grandit, le
        tableau de bord s'allonge. La section "Ajouts récents"
        est maintenant emballée dans un \texttt{<details>}
        natif, fermé par défaut, avec l'état ouvert / fermé
        persisté entre les rechargements via
        \texttt{localStorage}. Cliquez sur le titre pour
        développer. Les filtres indicateurs du tableau de bord
        (en retard, non rangés, gaps, catalogués récemment,
        retours récents) restent dépliés puisqu'ils sont le
        résultat d'un clic explicite.
\end{itemize}

\section{Nouveautés de la 1.2.2}\label{sec:whats-new-1.2.2}

La version 1.2.2 est un correctif de trois bugs en
\emph{defense-in-depth} sur 1.2.1, autour de la sémantique des
genres soft-deleted. Aucune migration de schéma, aucun breaking
change \string— routine
\texttt{docker compose pull \&\& docker compose up -d}.

Le garde de suppression de la story 8-4 empêche l'état orphan-FK
par la voie supportée~: on ne peut pas soft-deleter un genre qui
a encore des titres assignés. Ces fixes durcissent le contrat
côté lecture pour qu'une migration future, un
\texttt{UPDATE} SQL manuel ou un retrait du garde n'induise pas
silencieusement le bibliothécaire en erreur.

\begin{itemize}
  \item \textbf{Les liens de filtre genre périmés ne renvoient
        plus de listes vides silencieuses.} Ouvrez la home dans
        deux onglets, soft-deletez un genre depuis l'onglet
        admin reference-data, puis cliquez sur la puce filtre
        de ce genre dans l'autre onglet. Avant~: le SQL
        catalogue filtrait sur l'id du genre maintenant
        soft-deleted, la LISTE renvoyait vide, sans explication.
        Maintenant~: le handler home valide le genre cible du
        filtre, retire silencieusement la puce s'il pointe sur
        un genre supprimé, et affiche un bandeau d'information
        localisé (\emph{Ce genre n'existe plus \string—
        affichage de tous les titres.}) au-dessus des résultats
        pour expliquer ce qui s'est passé. Clôt l'issue GitHub
        \#112.
  \item \textbf{Les titres orphelins ne disparaissent plus du
        catalogue.} Les quatre requêtes SQL du catalogue
        (résultats de recherche, ajouts récents, catalogués
        récemment) utilisent désormais une jointure externe à
        gauche sur la table des genres, avec un
        \texttt{COALESCE} sur le nom du genre. Un titre dont le
        genre a été soft-deleted (orphan FK) disparaissait
        silencieusement de toutes les listes du catalogue~; il
        apparaît maintenant avec un placeholder localisé
        (\emph{(Genre supprimé)} / \emph{(Deleted genre)}) pour
        que vous puissiez le retrouver, lui réassigner un vrai
        genre et passer à autre chose. Clôt l'issue GitHub
        \#107.
  \item \textbf{Les pourcentages des statistiques par genre
        reflètent désormais la vraie part du catalogue.} Le
        panneau des pourcentages par genre sur la home
        calculait son dénominateur à partir de la somme des
        lignes affichées. Avec des titres orphan-FK actifs,
        cela gonflait le pourcentage de chaque ligne affichée
        (12 Roman + 8 BD + 5 orphan-Z affichait Roman à 60\%
        au lieu des 48\% véridiques). Le dénominateur provient
        désormais du compte total des titres actifs émis par
        la carte glance. En présence de titres orphan-FK, le
        total affiché est \(<\)100\%~; l'écart est le delta
        des orphelins et signale que certains titres pointent
        sur un genre soft-deleted. Clôt l'issue GitHub \#111.
\end{itemize}

La version 1.2.1 est un correctif de quatre bugs sur la 1.2.0.
Aucune migration de schéma, aucun breaking change \string— routine
\texttt{docker compose pull \&\& docker compose up -d}.

\begin{itemize}
  \item \textbf{Supprimer une série avec des titres assignés
        affiche désormais le bon message d'erreur.} Tenter de
        supprimer une série qui possède encore des titres
        renvoyait le bandeau générique \emph{Une erreur interne
        est survenue}~; la vraie cause (\emph{Impossible de
        supprimer X~: N titre(s) assigné(s). Retirez d'abord
        toutes les assignations.}) ne sortait que dans les logs
        serveur. Le handler reconnaît maintenant aussi la

        d'assignation, donc l'utilisateur voit le message
        actionnable et sait qu'il faut désassigner les titres
        d'abord. Clôt l'issue GitHub \#139.
  \item \textbf{Le bouton d'aide n'est plus imbriqué dans son

        l'assistant, étape préférences de l'assistant, création

        recouvrir le contrôle de formulaire. Clôt l'issue
        GitHub \#154.
  \item \textbf{Le modal de retour de prêt revient maintenant à
        la page d'origine après connexion.} Un utilisateur
        anonyme arrivant sur la page \texttt{/borrower/:id} et
        cliquant sur \emph{Retour} pour un prêt actif était
        envoyé vers \texttt{/login} puis déposé sur la liste
        générique \texttt{/loans}, perdant le contexte
        emprunteur. Le handler lit désormais l'en-tête
        \texttt{HX-Current-URL} envoyé par HTMX, valide le
        chemin via le garde same-origin existant et l'utilise
        comme cible de retour post-connexion. Clôt l'issue
        GitHub \#133.
  \item \textbf{Le corps de la réponse 403 Interdit s'affiche
        désormais dans la langue de l'utilisateur.} Un
        utilisateur en locale française cliquant sur une action
        réservée à l'admin en étant Bibliothécaire (ou tout
        autre flux produisant un 403) voyait le texte d'erreur
        en anglais au lieu de la traduction française. La
        locale traverse maintenant le helper de vérification de
        permission jusqu'à la réponse d'erreur, donc tout corps
        Interdit est rendu dans la langue que l'utilisateur
        voit déjà partout ailleurs. Clôt l'issue GitHub \#219.
\end{itemize}

\section{Rollback}

Le rollback \emph{n'est pas} un flux de première classe. Les
migrations de schéma avancent uniquement — il n'y a pas de
\texttt{down.sql}. La stratégie de récupération supportée est :

\begin{enumerate}
  \item Restaurer la sauvegarde de base pré-mise-à-jour
        (chapitre~\ref{ch:backup}).
  \item Réépingler le tag d'image à la version antérieure.
  \item Démarrer la pile.
\end{enumerate}

Cela fonctionne car la sauvegarde est cohérente avec le schéma
antérieur. Tenter de pointer une image plus ancienne sur une base
fraîchement migrée échoue au boot.
